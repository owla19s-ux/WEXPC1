## 2. 契约怎样产生

契约描述双方的行为承诺；接口列出可用操作与数据；协议规定交互的表达与传递方式。三者互相约束，不能仅凭类型定义或 JSON schema 宣称契约完整。

生成路径：
1. 从用户动作和结果出发，找出需要协作的责任。
2. 为每条边界明确发起者、接收者、输入前提、输出事实及唯一权威写入口。
3. 检查并发、取消、重试、撤权、关闭、更新和恢复时的行为。
4. 比较多条边界，提取确实共同的语义；专属语义留在所属领域。
5. 用真实调用链及故障试点验证；记录哪些假设成立、哪些需要改边界。
6. 再将可执行接口、版本规则、契约测试和模块施工说明同步落地。

目录、语言与进程是上述决策的承载方式，并非从职责名称直接推导。一个职责不要求一个顶层目录、进程或插件。

## 3. 候选组织方式与选择理由

| 方式 | 代价与收益 | 本轮建议 |
|---|---|---|
| 所有定义集中在一个全局协议包 | 容易找，但每个领域变动都牵动中央文件，容易出现万能命令与万能状态 | 不作为默认组织 |
| 模块各自定义全部语义 | 局部自由，但身份、错误、生命周期和兼容方式容易互不相认 | 不作为默认组织 |
| 小型公共约定＋领域公开契约＋扩展接入＋运行协议 | 需要明确归属，但能让专属修改留在模块，并保留必要互操作 | 作为本轮候选 |

这是契约内容的分组，不是四个必建技术层。运行协议可承载领域契约，扩展协议负责发现与生命周期；它们不能替代领域授权、任务验收或模型生成语义。

## 4. 全局责任与权威状态地图

“维护方”表示候选逻辑职责，不等于现有代码归属或已定物理目录。权威状态可以有缓存与投影，但只能有明确的正式变更入口。

| 逻辑责任 | 候选权威内容 | 主要公开协作 | 不拥有 |
|---|---|---|---|
| UI 页面与面板 | 草稿、选择、布局；持久化方式待定 | 查询、提交命令、订阅变化 | 权限结论、任务正式状态、执行成功事实 |
| 上下文组织 | Space／Group／Context 结构及其组织关系 | 创建、移动、关联、解除关联 | 被引用对象的数据与资源授权 |
| 角色／职责 | Role、Agent 身份和限定范围的职责绑定 | 身份查询、职责分配与变更 | 自动继承的资源权限、模型执行循环 |
| 会话 | Conversation、消息、分支与引用 | 发送、编辑后生成、读取消息 | 厂商协议、工具执行账本 |
| 模型调用协调 | 本次生成的绑定、进度和结算；归属未定 | 开始、观察、请求取消、查询结果 | Task 完成验收 |
| 连接管理与适配器 | 管理方保存连接配置与修订；适配器保存协议临时状态 | 能力发现、配置、协议调用 | 自行授予权限、修改业务任务状态 |
| 工作领域 | 项目、Task、正式要求、状态以及 Review／Verify 记录；内部拆分待定 | 任务变更、提交证据、验收 | 队列占用、外部执行成功的自造证明 |
| 调度 | 排队、领取、派发尝试、占用和恢复线索 | 投递、领取、释放、查询 | Task 正式完成状态 |
| 执行 | 操作、执行尝试、结果与回执关联 | 准入、执行、取消协调、结果查询 | 所有工作流业务规则、全部模型语义 |
| 权限 | 授权、审批、撤销及策略记录 | 判定、申请、批准、撤销 | Context 的组织结构、凭证秘密值 |
| 模板／工作模式 | 模式定义、专属结构和实例配置；实例数据归属需逐项明确 | 产生组合草案、专属视图和流程 | 第二套通用任务／连接／权限存储 |
| 扩展管理 | 包、兼容状态、注册、激活代次 | 发现、加载、停止接收、停用 | 所有领域操作的统一业务判断 |
| 存储／凭证／系统适配 | 技术事务、秘密保管、OS 访问机制 | 持久化基础服务与受控资源服务 | 由数据库表位置决定的业务所有权 |

Agent 身份与 Agent 工作循环分开。循环是消费模型输出、判断下一步和提出工具请求的运行责任；它与会话协调、调度、执行的具体拆分尚未确定，不强行新增一个循环平台。

## 5. 主要协作边界目录

以下编号只是文档索引，不能直接当作运行时能力 ID 或 API 名称。每项都是候选协作说明，不是用户逐项转交的施工卡。

| 编号／边界 | 输入与输出语义 | 权威写入口／授权 | 失败与并发约束 |
|---|---|---|---|
| C01 UI → 领域服务 | 带目标身份与适用修订的查询／命令；返回结果、拒绝原因或可追踪操作 | 目标领域正式入口；调用主体从可信会话建立，不能信任面板自报身份 | 过期编辑明确冲突；按钮消失不代表操作结束；重试是否安全由操作定义 |
| C02 Context → 对象引用 | 关联／解除关联对象，查询可见投影 | 组织关系入口维护其关系；对象内容仍归对象领域；读取须授权 | 移动与解除关联不隐式删除目标；目标不可见／失效可解释，避免泄露无权读取的数据 |
| C03 职责绑定 → 工作范围 | 指定执行身份、职责和作用范围，返回绑定记录 | 角色／职责入口；授权另行判定 | 改职责不静默改变在途工作的身份；重新授权或停止规则待定 |
| C04 会话／循环 → 模型调用 | 输入消息、模型、连接修订及可用工具声明；输出增量、完整工具意图和结束事实 | 调用协调保存运行事实，会话保存消息；模型调用与资源访问分别授权 | 断流不等于成功；取消请求与远端结果分开；详见模型推演 |
| C05 消费者 → 连接能力发现 | 查询当前连接支持能力、限制及可用性原因 | 连接管理综合适配器声明和连接配置 | 发现结果不是授权票据；状态可能变化，执行时仍需检查 |
| C06 调用协调／执行 → 适配器 | 经过准入的具体操作与绑定信息；返回协议结果、错误、进度及证据 | 适配器报告外部观察，公共协调保存调用事实；具体网络和秘密使用方式未定 | 插件不能自行改 Task 或批准权限；超时不推断未执行，不盲目重试 |
| C07 工作／循环 → 调度 | 工作引用、目标、依赖与范围；返回排队／派发事实 | 调度维护投递与占用；工作领域维护任务状态 | 重复投递、领取失效和重启恢复须有明确策略；有 Task 的工作与无 Task 的普通调用均可表达 |
| C08 调度／直接调用者 → 执行 | 操作意图、目标、执行身份、范围、修订与必要授权上下文；返回操作定位及结果 | 执行准入与最终资源边界；不得以“已入队”代替授权 | 等待期间撤权须影响后续执行；派发尝试与执行尝试不同；不得承诺跨系统恰好一次执行 |
| C09 受控操作入口 → 权限 | 主体、入口、动作、资源、范围及相关修订；返回允许／拒绝／需审批及理由 | 权限维护策略与决定；OS／资源检查保留在实际执行边界 | 判定失效和撤销传播需有机制；相同政策不在 UI、模板、连接器各复制一份 |
| C10 执行／审查／验证 → 工作领域 | 有来源、目标版本和覆盖范围的证据及结论 | 执行写操作事实；工作领域按规则接受记录并改变任务状态 | 命令成功不等于任务通过；旧提交测试不能证明新提交；独立 Review 与实际 Verify 不互相代替 |
| C11 模板／结构草案 → 通用领域 | 可审阅的对象／关系变更方案；返回真实对象映射及逐项结果 | 各领域正式入口；用户确认结构不等于授予外部操作权限 | 多模块创建不假设天然原子；部分成功可识别、可续接；撤销不得误删用户后续修改 |
| C12 扩展管理 ↔ 能力／UI 提供者 | 声明、依赖、兼容范围和生命周期；发布能力及面板 | 扩展管理维护注册；领域维护业务事实 | 必需贡献准备失败不暴露半就绪；在途工作绑定原代次；卸载不删除历史 |
| C13 领域 ↔ 持久化／恢复 | 保存权威记录、读取修订及恢复线索 | 领域定义数据意义，基础设施提供存储机制 | 数据库事务不涵盖远端副作用；恢复先核对未知结果，不直接重复外部写入 |

读取、命令、事件三者不能互相冒充。事件用于报告事实，不因为发布一个事件就获得执行权限；事件总线也不是默认必建组件。

## 6. 五条主链的推演检查

### 6.1 普通对话

用户发送 → 会话记录输入 → 调用协调固定本次绑定并检查调用资格 → 适配器请求模型 → 协调核验输出和结束 → 会话保存消息 → UI 展示。

出现工具意图时，由工作循环提出执行请求，经权限与执行边界调用连接器，再把真实结果反馈模型。整个过程不强制 Space、模板、Project 或 Task。普通聊天是否经过调度，取决于排队和并发需求，不为了统一强制走任务施工链。

需要验证：重载页面不丢事实；调用崩溃保留部分输出；取消与成功竞争不重复结算；关闭页面是否继续生成仍属产品待决事项。

### 6.2 Space 组织与跨对象引用

创建 Context → 选择对象／资源引用 → 组织入口保存关系 → 读取目标对象的授权投影。

移动 Context 仅改变组织事实，不自动迁移关联任务、外部文件或角色权限。解除关联不等于删除目标。跨领域关系由谁保存、对象删除如何清理引用尚未确定；候选是关系语义所在领域维护引用边，并通过目标公开入口校验，而不是创建全知中央关系表。

需要验证：移动后对象 ID 保持；无权对象不暴露内容；删除目标后引用可诊断；无 AI 配置也可手工组织。

### 6.3 连接配置与调用

扩展能力就绪 → 用户建立连接 → 保存配置与秘密引用 → 查询支持能力 → 选择能力 → 实际调用时重新判定可执行性。

必须区分包、适配器、用户连接、模型和授权。多个连接可复用一个协议实现。配置修改仅影响后续绑定；撤权则必须影响后续受控动作，不能被“固定配置快照”绕过。

需要验证：新兼容厂商只加配置；新协议在包内完成；停用连接阻止新调用，历史记录仍可查。

### 6.4 任务执行、审查与恢复

工作领域建立目标与验收条件 → 分配职责 → 调度派发 → 执行者在有效范围内运行模型和工具 → 保存操作证据 → 对准确版本审查与验证 → 工作领域依据规则更新正式状态。

派发成功、执行者声称完成、文件提交、Review 通过、Verify 通过是不同事实。重启时读取各权威记录并核对关联，不把“队列没有任务”理解为已完成，也不把“没有收到回执”理解为未执行。

需要验证：重复投递不会重复外部写入；旧领取者结果可按身份和版本辨别；某个 Agent 失败不覆盖别人的记录。具体领取租期、重复识别和补偿方式待运行方案决定。

### 6.5 模板应用与视图编辑

选择软件开发模式或从对话生成结构建议 → 查看组合草案 → 经确认调用各领域入口创建／关联 → 保存实例映射 → 模板视图读取并编辑真实对象。

模板拥有专属表现和模式逻辑，不复制权限、连接或 Task 正式状态。视图坐标和视觉连线不自动改变业务关系；如需要建立真实关系，显式提交相应领域命令。

需要验证：部分创建失败有明细和续接方式；重复点击不重复创建整套对象；模板更新不覆盖用户修改；没有模板仍可普通对话和手工组合。模板实例的专属结构与通用对象分界仍待细化。

## 7. 最小公共约定：候选范围及禁止过度统一

| 候选共享内容 | 可以统一的部分 | 保留在具体领域的部分 |
|---|---|---|
| 身份与引用 | 稳定身份、资源类型／来源定位的表达原则 | 对象属性、层级和业务关系 |
| 关联与版本 | 调用关联、配置修订／对象修订／实现代次需要明确区分 | 各自比较规则、生命周期和存储 |
| 错误 | 可识别类别、用户可理解原因、诊断关联、敏感数据脱敏 | 协议错误、领域冲突及恢复方式 |
| 取消与结果 | 取消请求不等于撤销副作用；保留已知／未知事实 | 模型停止、进程退出、文件写入的不同结束语义 |
| 授权上下文 | 能够追踪主体、入口、动作、资源和作用范围 | 权限算法、审批规则、OS 检查 |
| 兼容性 | 明确提供方／消费者接受的契约版本与不兼容反馈 | 包格式、序列化、具体版本编码方案 |
| 证据 | 来源、目标版本、关联操作及获取时间可追踪 | 测试输出、文件内容、审查结论等专属结构 |

不设计包含全部字段的万能信封；本地纯查询不必承担跨进程流调用的全部元数据。不同领域的 ID 不因都是字符串就可互换。错误的“可重试”标记不能单独证明副作用可安全重做。

调用终态、远端效果是否确定、用量是否已知可以是不同维度；避免一个全局 status 枚举吞掉信息。

## 8. 依赖与契约维护方式

候选原则：
- 消费者调用提供方公开契约，不导入其内部实现或直接写其数据。
- UI、模板和工作循环可以组合多个公开服务，但不复制权威状态与权限政策。
- 扩展管理只组织接入和生命周期，不变成所有业务操作必经的万能路由器。
- 平台服务不依赖具体厂商、模板和任务业务；接口定义是否需要提取成独立包，依据真实循环依赖决定。
- 同库不等于可以跨领域直接写表；同包不等于可共享秘密或绕过授权。

全局文档只维护边界索引、公共原则及未决事项。领域契约跟实际维护单元走；每个公开契约记录目的、消费者、输入前提、输出、权威状态、失败／取消／重复处理、权限、兼容与验证例子。MODULE.md 链接该定义，不复制第二份 schema。

未来机器定义尽量单一来源生成客户端／校验器，但必须保留行为测试；代码生成不能验证取消、重试和恢复语义。新厂商的专属参数不进入全局公共类型，除非确实产生跨厂商消费需求。

## 9. 变更与兼容的候选规则

- 包版本、公开契约版本、数据版本和激活代次分别处理，不以单一版本号代替。
- 新增可选字段是否兼容，取决于旧消费者处理未知字段的行为；不能自动认定兼容。
- 修改默认行为、取消承诺、授权要求、错误含义也可能破坏兼容，即使函数签名不变。
- 破坏性变化要明确拒绝旧消费者、提供显式适配，或规划迁移；不静默解释成新语义。
- 数据迁移成功前后的回退条件分别记录；热替换接口兼容不等于数据能回滚。
- 已获批准的旧请求不因升级自动得到新权限。
- 契约变更同步提供方、受影响消费者、文档与测试；不相关模块无需为专属实现变化陪改。

具体版本范围、编码格式、IPC、消息排序、背压、重连和重放规则，在运行方案试点中决定。需要可靠事件传递的链路还应明确确认点与重复处理；本文件不默认引入消息队列。

## 10. 关键未决项与所需证据
