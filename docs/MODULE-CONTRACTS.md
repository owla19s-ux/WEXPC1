## 3. 提供/消费关系与依赖方向

以下是能力依赖，不是完整源码import许可表。提供方维护语义，消费者依窄端口；app注入实现。源码边、运行能力边、装配边分别检查，双向观察不强迫双向import。

| 提供方→消费者 | 必需能力/证据 | 方向与禁止绕行 |
|---|---|---|
| shared→各域/app | 提交成功/未提交/未知、权威修订回读、限定路径/秘密可用性 | shared不import领域实现，不自行解释Task/授权 |
| permissions→各正式入口与connections | 当前主体/入口/动作/资源决定和依据，非允许不得动作 | 事实宿主核验注入，permissions不反查所有领域私有库 |
| space→UI/views/对话/工作域 | 获准Context/组合引用、本体/关系修订和定位 | 外部文件版本另由实际资源owner提供，不把关联变授权 |
| AI→对话/工作域/选择投影 | 配置职责及本次不可变依据，当前获权历史解释 | 新工作准入与历史解释分开，不读“最新”覆写旧轮次 |
| connections→AI/对话/工作域/诊断 | 能力元数据、受控Operation、尝试观察/控制差异 | 消费者不解析厂商协议，connections不写Task或消息权威 |
| workflows→对话/UI/views/modes | 显式任务创建、定义/Task/核验投影和受控编辑 | 一般对话不必创建Task，视图不倒写任务 |
| workflows/runtime→connections（宿主注入） | 无Task也可用的资源协调依据/修订、未决占用和释放证据 | connections不能私有import runtime；预检与派发复核复用同一意图/协调引用 |
| 对应领域→connections回调（宿主注入） | 本次目标最小查询/写操作及领域修订规则 | 外部身份/范围每次核验，不给全Context/数据库 |
| 通用域→modes | 专业组合需要的通用创建/查询/编辑 | 源码依赖是modes消费通用出口；通用域不反依赖具体模式 |
| modes/领域→views | 专业规则身份/获准对象关系和来源版本 | views经注入消费；modes不导入views实现决定业务 |
| 领域窄桥→UI | 获准查询、意图提交、原关联恢复与状态证据 | renderer不导入Node/凭证实现；面板位置不改变业务owner |

装配根可以引用公开业务面和宿主专用装配面，不能以装配名义任意深导入private。运行回调端口可由消费者声明所需形状，但不能削弱提供方授权/版本前提。完整自动检查规则及例外管理见[tools施工规格](../tools/README.md)。

## 4. 四组优先边界审查结论

| 边界 | 责任收敛及重要失败例 | 相关契约 |
|---|---|---|
| Space↔Permissions↔AI | Space写选择、AI写职责、permissions写许可；解除关联/撤任不隐式删目标或撤权，后续资格仍按当前事实重判。入口B不能用入口A对同Context的许可；重装旧许可不复活 | SPC/AIC/PER行为样例；非对话入口映射D |
| Conversations↔Connections | 消息/逻辑生成与Operation/Provider分开；已落盘输入、外部接受、流式暂态、定稿保存分开观察。G1迟到不覆盖G2；重发是新生成，不重放未知工具 | 对话公开表+C01–C05；提交ACK丢失只读回、不再调模型 |
| Workflows↔Connections↔Permissions | 分配/准备不执行，连接宿主准入/保存attempt/适配；工作域按证据核验验收。runtime预检与最终准入绑定同一协调引用；Task与无Task同资源均受阻。所有非明确允许均零动作 | W01–W07+C02–C05+PER；unknown不释放占用、不盲重试 |
| Workflows/modes↔Views | 执行定义/依赖属工作域，专业对象关系属模式/原域，出现映射/布局属views；图上同名不等同机制。草稿不覆写运行结果，不直接采用ReactFlow Draft | W01/W07、modes与views；模式单向消费通用域 |

以上收敛没有新增全局状态管理器/协议总线/插件框架。四组的样例为设计验收要求，不是本轮已运行结果。原型证据只限定历史已测范围，未把参考函数提升为正式接口。

## 5. 接口、协议与独立验收

[app/COMMUNICATION.md](../app/COMMUNICATION.md)区分同进程、renderer/Node、独立插件、外部Agent和文件/Git/远端服务；维护可信身份、请求/意图/attempt关联、错误、能力协商和恢复边界。内部重构、兼容扩展、破坏语义与wire/data分别判断：TS仍兼容但默认权限/unknown/取消/重试变了，仍可能破坏。

[tools/README.md](../tools/README.md)给出逐模块施工卡、允许范围/公开与私有、替身/真实双方样例、实际dependency-cruiser规则片段、模块SCC/环境隔离/影响检查与例外要求。配置片段不等于门禁已安装；必须存在真实源码，解析错误或空图不能当通过。只读契约设计不得触发产品依赖安装。

每模块未来交付证据分四层：真实本域行为；公开能力的提供方/消费者/替身一致样例；真实装配与相关外部适配；最后L01–L12及故障场景的系统组合。模块通过不等于组合通过；缺真实提供方时明确限制，不用用户反复“继续”驱动碎片施工。

## 6. 待决、实验阻塞与最小处置

| 编号/等级 | 未决条件与受影响能力 | 本批处置/解除门槛 |
|---|---|---|
| D01 非对话权限三层映射 | Task/独立工具/回调如何对应第三层，不伪造对话也不永久禁用 | PER给明确推荐；未批准入口策略不颁有效许可；不影响已定义对话拒绝规则评审 |

| C02 删除竞争/D02 删除策略 | 引用/在途影响快照之后仍可能变化；强删/回收站保留策略 | SPC05实际删除暂缓，需竞争屏障或等价可证方案；不阻止解除引用 |

## 7. 交付核对与后续依赖

本批按模块完成设计→独立施工者交叉审查→修正→静态检查→分组提交，不按链路分批。检查相对链接、模块能力/样例/依赖覆盖、只改Markdown、基线及并发HEAD、远端内容；没有运行产品测试，也不复报历史测试为本次通过。

后续可并行细化space/AI的组织配置、对话的逻辑生成、views的布局配置与工作域的定义/Task记录，但均消费明确窄依赖替身；shared和permissions的最小结果语义先由消费者共同确认。真实连接准入需存储/判权/资源协调；真实工作流运行再组合连接事实；模式和UI只通过领域入口。安装/重装、有限次数、实际删除、未知资源释放与自动验收不得跨过上述C/D门槛。此处是准备程度与依赖说明，不是本轮正式施工指令或版本改期。

本批设计完成的界限：成熟域均有独立可评审规格及依赖行为，跨域矛盾已做静态修正；最终TS签名、wire、算法和C/D不要求本批全部解决。未来按能力成熟度选择施工范围，不能将“设计批次完成”误写为“所有接口冻结/产品已验收”。
