# G｜下一阶段按模块施工顺序

**可以转入有边界的模块独立施工；本批只交准备度，不执行正式产品。** 不按H链路拆工程包，不提前安排红色能力。每包遵循README/CONTRACT→本域真实测试→实现→同验收向量提供/消费→真实装配→组合回归。

| 顺序/模块包 | 产物与验收 | 依赖/可并行 | 排除/必须先解 |
|---|---|---|---|
| 0 契约与技术基础窄面：shared、permissions、app分别负责 | SH提交三分/CAS/原关联回读、PM可信事实/拒绝/撤权、APP窄装配；分别有本域真实测试和失败用例 | 三owner协商公开最小语义，装配由一人串行集成；非一个跨域大包 | 不做Windows凭证承诺、有限次数、非对话有效许可；需实际存储驱动故障证据，不复用Python当产品 |
| 1 space组织引用 / AI配置依据 / views布局配置 | 三个绿色包：Context独立/多放置不复制；角色选择/职责/授权分离、旧配置不污染在途；布局不改执行事实 | 可以并行，各自只写本域；消费SH/PM/CN元数据替身，真实基础就绪再对照 | 不删本体、不搬目录、不建记忆/多图执行数据层；依赖不足不伪装整链已通 |
| 2 conversations记录 / workflows定义任务证据 | 无Task会话消息/段落版本、来源；定义/实例固定、Task/Requirement/Artifact/Verification及等待诊断 | 可以分模块并行，consume同SH/PM/AI/Space端口；不共享可变模型 | 流式外发/调度/自动验收不顺手施工；D03/05相关能力延期 |
| 3 connections边界+单本地适配 / workflows协调真实集成 | CN意图/attempt/unknown查询真实持久化；WF用原关联读取，真实崩溃窗口无盲重派；资源协调覆盖有/无Task | CN/WF各自实现者对接，公用文件串行；先本地无费用操作，再外部 | F01真实回调/别名、F03发送复核、F05owner/政策、F06外部写隔离、F07快照；未验不宣安全并发 |
| 4 connections/dsh单个固定能力 / dsh独立插件取证 | 真实固定Agent成功任务→指定目录→回执/版本核验；插件兼容保持另一路证据 | DSH连接器与原生实验可以并行，但不能互相代证；只用获准无费用环境 | 本批不调付费模型；缺免费真实执行条件继续标阻塞，不能以协议fake完成 |
| 5 UI真实桥 / modes窄软件组合 | UI通过真实领域桥呈现当前获准状态；模式只建议/显式创建，不授权启动；跨域部分成功可恢复 | 先有提供方，再装配；UI可提前用替身独立写稳定页面范围 | 不冻结全页面/行业模型，D01/03/04/05受影响功能暂缓 |
| 6 app/SH/UI Windows平台接线与组合 | X09安装→路径/锁/凭证→异常恢复→卸载留数据全证据；按既有H完整组合 | 可提前准备构建/操作单；实机/最小EXE就绪才做E4 | Windows环境、安装/退出策略与真实平台机制；Linux不能替代 |

每包准入需记录main SHA、契约版本/消费能力、允许目录、禁止范围、失败/取消/超时/unknown样例、测试命令、C/D及提交证据。绿色不要求全部签名提前冻结；实现中只对实际消费者确定最小接口，有破坏语义变更就记录并同步。

**必须先实验**：真实CN↔WF重入/资源别名、持久提交ACK丢失/派发窗口、F03可信来源到真实发送、外部Agent接管/停止/直接写、产物核验后变更与快照、Windows锁/安装生命周期。**必须等产品决策**：D01/02/03/04/05/06/07对应受影响动作，见[集中清单](DECISIONS.md)。

首轮验收目标是可独立验证的真实本域能力及窄依赖，之后才连成完整链路。没有必要再追加一轮无边界架构研究，也不能跳过这些明确门槛宣布全平台开工。
