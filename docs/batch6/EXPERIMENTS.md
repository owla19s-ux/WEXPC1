## 失败与修复记录

1. 首次启动新Python测试因实验模块尚不存在而失败（ModuleNotFoundError）；这是测试骨架尚未建立，**不是捕获产品bug或完整TDD证据**。
2. X01增加“解除B后A/P仍受阻”断言后真实失败：[负结果](evidence/wait-negative.txt)。根因：夹具将持有事实寄托于等待边存在，删除入边误抹占用。修为`holds`独立事实，只释放对应owner持有；同断言与全套18项通过。这是实验模型修复，不是已修复WEX产品。
3. X03增加二次摘要再传播断言后真实失败：[负结果](evidence/propagation-negative.txt)。根因：二次derive只用新targets，丢原限制。修为继承已验证内容版本的范围交集和来源链；同断言及全套通过。可信sidecar仅夹具输入，**不证明恶意插件不能伪造sidecar**。
4. X05错误算法保留为可重复负对照，测试预期其超卖，不能把该项绿色理解为错误算法安全。SQLite条件扣减为候选正对照。
5. DSH throw/missing模式预期退出1，测试框架验证其失败/清理，不是测试套失败。复用npm配置有`Unknown env config http-proxy`警告，不影响退出码；未以清理代理环境绕过网络限制。

## X09解除阻塞后的Windows操作单

使用隔离Windows VM/标准用户及第二用户、可回滚磁盘，先有最小Electron产品/安装包和明确D04策略：

1. 自选安装盘+独立数据根，记录进程所有落盘位置；中文/空格路径、bootstrap丢失/重选、缺盘与只读分别留证。
2. 同用户重复启动、不同安装/第二用户同根、异根profile；核对SID/根身份/锁与写计数，伪造旧PID/残留文件不得获得写权。
3. 真DPAPI/safeStorage配置；正常重启可用与卸载重装/系统重装必须重配分别对照，不记录秘密。
4. 在未决操作/数据库写入/迁移阶段强杀；重启先读原attempt/根，submit增量必须0；恢复产物hash与核验版本。
5. 休眠/网络代理变化、系统通知后撤权、关窗/退出依D04留截图及操作记录；未获权标题不出现在旧通知/搜索。
6. 升级成功/迁移失败/程序回滚/卸载默认留数据，再安装接回；保留原件和版本诊断，不递归删除外部引用。

通过条件：每步有环境/版本/SID脱敏/实际路径/操作计数/数据库回读/产物hash/失败恢复证据。只有交互截图不够；不以Windows目标交叉编译代替实机。

## 对契约的反馈

证实需要分开的事实：等待边/资源持有，定义/实例/轮次/attempt，内容版本/传播许可，插件已卸载/原操作仍在途，预留/实际成本，执行权/外部停止，Artifact/Verification/Acceptance，应用实例/数据根写权。机制可行性提高，不等于产品端口/OS安全边界已兑现。保留全部E3/E4及剩余C门槛，不据此批准D。
