# D｜依赖与独立施工审查

本批按既有11域审查。当前产品代码大多不存在，**不能对文档跑import图并称无循环依赖**。以下为能力/装配依赖分析，唯一已实跑的本地技术耦合在实验目录；正式实现出现后必须另跑真实源码图与运行故障验证。

## 提供方、消费者和权威

| 提供方 | 消费者需要的最小语义 | 禁止耦合 |
|---|---|---|
| shared | 技术提交/未提交/未知、修订回读、限定根/秘密机制、日志容量 | 不导入业务域；不解释Task/许可/验收 |
| permissions | 当前主体/真实入口/资源动作的决定、撤销代次、历史依据 | 不反查各域私库；角色/预算/选择都不授信 |
| space | 获准本体/放置/组合引用和定位 | 不复制AI/消息/Task/来源正文；关系不搬文件 |
| AI | 配置/职责版本、新工作依据与历史解释 | 不调用模型/维护session/写Task分配 |
| conversations | 消息/输入/生成/来源关联、显式转Task | 不写Operation真相、流片段不直接执行 |
| connections | 能力/准入、Operation/attempt、真实观察/控制、原关联查询 | 不写Task/验收；不维护第二预算/权限账本 |
| workflows | 定义/实例/Task、等待/占用、核验/验收；候选窄限额协调 | 不解析Provider、不让无Task调用创建流程；候选不强定owner |
| modes | 可选专业规则/对象/组合建议及版本 | 通用域不反依赖software-development；模式不调用适配器 |
| views | 环境中立布局/筛选、带源版本投影、编辑意图转交 | 不存执行状态副本、不把图边当Task依赖 |
| UI | 导航/临时交互/窄桥呈现 | 不深导Node/凭证/数据库、不绕owner写store |
| app | 可信装配/入口事实、生命周期协调、平台诊断 | 业务域不import app；装配不得导出万能容器/全库 |

装配根消费公开面，向消费者注入所需最小接口。私有实现可独立替换；领域通知只作失效提示，丢通知后权威查询仍应正确，不以可靠总线为前置。

## 未关闭的运行环与处置

| 编号 | 风险/现状 | 本批结论与解除条件 |
|---|---|---|
| DEP01 CN→协调→WF→CN | 权威区分不代表运行无环；持事务/独占槽回调会互锁 | F01分别持久等待与持有，事务外返回等待/unknown；X01只证图模型。真实宿主重入/回调交错和资源别名尚C，正式安全并发暂缓 |
| DEP02 PM输入事实↔领域变化 | 判权后内容/目标/代次可变化 | 请求绑定真实入口/内容版本/实际目标，出口再复核；X03仅到本地outbox，真实发送提交点/IPC重放待验 |
| DEP03 领域↔SH跨库关联 | Task保存/attempt提交/实际派发之间无默认全局事务 | 原意图/attempt查询+三分提交；不得编造恰好一次。可独立施工本域持久记录；组合故障窗需真实两方 |
| DEP04 DS原生Service↔CN出口 | 内部原生调用不自动经WEX，卸载不能证明停止 | 真实发现/代次/控制能力适配后经CN授权记录；X04只是样本宿主，不能把它当真实WEX控制墙 |
| DEP05 APP锁↔WF占用 | 根锁释放后旧外部操作仍可能运行 | OS写锁只保护数据；恢复先查原attempt/未知占用。X08不解除业务锁或旧授权 |
| DEP06 MD↔VW↔UI | 同名节点/图边可能被误当通用执行语义 | 专业规则属MD、布局属VW、执行定义属WF；按版本公开投影，真实集成前不默拷ReactFlow Draft |

没有发现需新建顶层“总管”的依据。预算窄协调接口若造成真实不必要反向依赖，再比较等价技术端口与局部性；本批不自行另立预算系统。

## 独立测试与组合测试

1. 提供方：本域真实行为+提交失败/unknown/修订冲突；测试只写本域临时库。没有对方实现时通过窄替身注入，但明确证据等级。
2. 消费方：同输入/输出语义运行契约替身，包含拒绝、不可判定、旧版本/晚到、提交成功ACK丢失。不能只验证字段结构或mock“被调用”。
3. 双方一致：共享的是验收向量和契约版本，不是共享可变业务模型；真实提供方跑相同断言，防替身总成功。
4. 真实集成：app装配真实PM/SH/目标域/CN，注入回调重入/崩溃窗口，记录持久状态/副作用计数。最后按[组合矩阵](COMPOSITION.md)逐步升证据，不把局部绿传染给整链路。

## 多AI施工与修改边界

每张模块施工卡必须记录：main基准SHA、提供方CONTRACT文件blob/版本、所消费能力段、输入输出/失败样例、允许目录、禁止目录、C/D排除、真实测试命令和交付证据。模块owner维护公开契约，消费者不得同时改权威数据定义；跨域破坏变更先由提供方记录影响/兼容计划，再同步受影响消费者。

- 常规在main，提交前核远端HEAD；落后先检查他人改动，不覆盖，不以同一初始SHA批量抢写。
- 可以并行的是不共享文件的模块包；根README、全局索引、装配文件由单一集成人串行更新，其他执行者提交就近材料/集成需求。
- 契约变更日志记录“旧→新、原因、受影响消费者、验收向量、迁移/兼容、是否破坏”。仅TS编译仍过不证明行为兼容。
- 同一公开契约由一人写，读取者锁定版本。版本漂移时先重审影响再继续，不凭聊天摘要施工。
- 不分发同时改shared、permissions、workflows权威定义的跨仓“大链路施工单”；这些是不同owner的接口协作。
- 有并行资源冲突/高风险实验才考虑必要隔离，普通文档不造临时分支；不触发Actions。

本批依赖审查完成的是上述边界/问题清单，未安装源码依赖门禁。真实源码产生后按tools既有规则跑非空import图/SCC、renderer越界及模式反依赖检查；规则本身应有故意违规负例，空图/解析失败不能绿。
