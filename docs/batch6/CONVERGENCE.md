# A｜F01–F09业务契约收敛

基线与证据等级见[总览](README.md)。原始问题均来自[第五批§3](../research/COMPLEX-CONTRACT-STRESS-REVIEW-2026-10-31.md)；F01/F03/F05还纳入最新main的“第五批交叉收敛”段。下文“收敛”指业务不变量/验收条件已明确，不代表未批准机制升A、C/D关闭或产品代码存在。风险：F01–05/F07–09较高（重复副作用/越权/损坏或误验收）；F06一般至较高（交接失控）。

## F01 等待协调、环与恢复

- 来源/场景：W03/W05/W06、C02/C05；H01/H13/H22。原契约有冲突阻派及unknown不释放，后补禁止持事务/独占回调同步互等；仍缺等待与持有事实的区分、环解除后的残留责任。
- 权威/负责：workflows/runtime拥有等待关系、持有范围、推进与交接；connections拥有操作执行/停止观察；shared只提供提交与技术锁；permissions决定谁可解除/继续。无需新增顶层等待模块。
- 公开需求：runtime提供可见等待依赖/环诊断、证据驱动更新；connections提供原attempt观察/停止能力差异；不得把bool busy当完整等待依据。关系至少表达等待者、被等待者或资源/审批、所属实例/轮次、持有范围、原因、观察时刻；字段形式未冻结。
- 收敛规则：等待边和资源占用独立。取消等待、超时、审批结束可结束相关等待，不能证明资源停止；已证未开始/已停可解除对应占用，其他unknown保留。正常等待有可追踪未满足前提；超时是期限事件；可见图有环是死锁风险诊断，不等于已证明外部进程死锁。独立资源R可继续。自环也报告。恢复先重读等待、占用、原attempt，按当前许可/依赖重新计划，不以超时重派。
- 实验/影响：X01复现持久环和“解除B误释放A占用”反例，修夹具后通过；说明两类事实不可混存为一个存在标志。另在已发生真实文件副作用后强杀，恢复同意图不再写，副作用文件仍1行；只证明保守拒重派，不证明自动完成/恰好一次。尚未验证所有资源别名、回调重入、审批跨进程及大型图活性，不承诺实时/全量消环或恰好一次。
- 候选/争议：锁顺序、全量申请、图扫描/SCC频率、可中断等待候选B/C；人工强放unknown的主体/条件D04。受控非Task入口仍经窄协调，不能强依赖完整工作流。正式并发推进保持黄色。

## F02 定义、实例、汇合与轮次

- 来源/场景：W01/W03、views/UI/modes；H18/H23。原契约固定修订但未足以区分未选分支、unknown、重试和新轮次。
- 权威/负责：workflows维护不可变已发布定义、实例绑定、分支选择、轮次与attempt；modes提供版本化专业规则；views/UI仅投影/编辑草稿；connections提供关联外部结果。
- 公开需求：按版本读取定义、显式创建实例、读取实例绑定、按实例/节点/轮次/attempt接收结果、查询汇合依据；不允许消费者按同名节点拼结果。
- 收敛规则：草稿修改发布新版本，旧实例继续原版；不隐式迁移。实例固定规则/输入依据；不支持原规则则阻塞，不套最新。分支选择留证，未选不同于失败/unknown；汇合必须声明规则。隔离实验仅支持“所有已选分支成功”，不是已选定全部产品汇合类型。新循环轮次有独立身份，失败重试属于原轮次的新attempt；迟到旧轮次/旧attempt不能完成新轮次。未知副作用先核对，不能仅因为attempt号增加就重派。
- 实验/影响：X02真实库保存r4/r5、I1/I2、分支/轮次及子进程回读；重复相同结果幂等、同attempt冲突拒绝。没有引擎/ReactFlow→运行定义真实接线。可做定义/Task/证据记录，不冻结引擎/消息协议。
- 候选/争议：迁移映射、循环上限和高级汇合B/C，首次支持范围/自动执行策略若改变产品行为则D；现阶段明确不实现迁移，不阻基本定义施工。

## F03 读取、外发与衍生传播

- 来源/场景：PER01/02、CV输入/定稿、C02/C05及最新交叉收敛；H14/H24/H26/H27。原契约分读/发，但保存摘要、多次加工可能丢来源限制。
- 权威/负责：实际内容owner（conversations输入/生成或workflows产物依据）保存版本及可信来源；permissions独占传播决定；connections核对实际出口并记Operation；space只引用，AI不新增来源总账。
- 公开需求：内容owner提供指定版本/范围的来源依据；permissions接主体/入口/动作/内容依据/实际provider+实例+接收端点重新判断；connections执行前绑定待发送内容和真实目标。保存本地、读取、跨Context披露、对外发送是不同动作。
- 收敛规则：可读不推导可发；摘要/翻译/改写/保存不降级限制；多来源组合不能因其中一份公开而公开整体，限制不能以并集放宽。来源缺失/冲突/不可信或内容已变，自动出口阻断并给不泄密诊断；不能相信模型自报“脱敏”。每次再传播重新检查，读取后撤权必须阻新出口；已发送不能承诺收回。
- 实验/影响：X03真文件→确定性摘要→保存→再摘要→本地outbox，二次摘要重置目标范围的负对照曾越权；改为继承交集后通过。目标替换/读取后撤权/内容篡改/缺来源均零outbox。没有真实AI、网络发送、可信来源认证或任意DLP证明；outbox到发送的TOCTOU仍C。副作用出口必须消费此前提，普通聊天不用造Task。
- 候选/争议：来源合成编码/可信绑定B/C；人工审查/降级/跨Context发布谁可批准D06，未定不自动放宽。真实外发能力黄色，不影响组织/配置。

## F04 DSH原生插件与WEX连接器

- 来源/场景：DSH README、C01/C02/C05；H12/H25。原有hello加载不覆盖双消费者/在途卸载/实例代次。
- 权威/负责：DSH原生环境管理自身依赖、包版本、Service与生命周期；WEX连接器适配公开发现/就绪/调用能力，WEX边界负责授权/操作记录，workflows负责任务/验收。仓库`dsh/`是独立实验；`connections/dsh/`面向独立外部Agent；不能把前者搬成主进程执行环境。
- 公开需求：实际环境报告包/实例/代次、能力版本、依赖就绪/失败、支持的控制与释放证据；connections不能只因目录有文件就注册可调用。发现/加载不授调用权。经WEX出口的调用记录Operation；DSH内部直接调用不自动被WEX授权墙覆盖。
- 收敛规则：停用阻新准入，卸载不等于在途已停；旧回调保留原实例/attempt归属，不绑定新同名实例。共享依赖仍被其他消费者使用时不误删；依赖失效阻新调用且诊断范围，不宣称整个宿主必然存活或安全沙箱。依赖版本不兼容必须显式不可用。
- 实验/影响：X04真实固定Core+Loader重建/Bundle/失败进程和新增双消费者、共享Service、旧引用晚到、新代次/清理通过。不是完整DSH插件管理、第三方包兼容或WEX真实集成；“进程隔离”只限受控启动错误，资源/网络权限仍未证。
- 候选/争议：发现映射/能力注册形式与ABI协商B/C；不建完整自有插件系统。E3成功闭环/Windows故障恢复阻塞；DSH依赖不成为内置连接器前置。

## F05 预算、并发与未知消耗

- 来源/场景：W05、C02/C04、SH容量、UI反馈及最新预算补丁；H14/H29。原契约缺无Task准入及并发预留证据。
- 权威/负责：限额政策/预留owner推荐workflows/runtime的窄协调能力（B，未定案）；connections提供估算/观察/账单、原attempt；shared提供原子技术提交；app健康/容量不成为预算账本。
- 公开需求：按主体/真实入口/资源池/单位/政策修订申请与查询预留、按证据对账/释放；无Task也可消费。没有预算政策的调用不能被擅加无限收费或虚构预算拒绝。金额/调用次数/并发槽/磁盘容量是不同维度。
- 收敛规则：同池最后额度必须原子竞争；预留关联意图/attempt，相同意图不同金额冲突，重试新attempt可能新增成本，不能复用已结算意图重复调用。发出后失败/unknown/仅请求取消不自动退还；已证未开始可释放，最终用量差额真实记录。实际超预留可出现负可用量并阻后续，不把账单抹平为预算。预算许可不能代替权限。
- 实验/影响：X05两真实进程负对照超卖，SQLite事务条件扣减仅一赢家；预留提交后强杀仍占额，最终对账/重复结算/差额/新重试通过。实验是单库单单位计量，不验证远端账单、预留前/外发后所有崩溃窗口、跨池/币种或公平性。
- 候选/争议：runtime owner和限额算法仍B/C；硬/软产品承诺、超额动作/共享池优先级D07。正式费用引擎暂缓；不能要求所有API/工具经工作流。

## F06 人工接管与执行权

- 来源/场景：W03/W06、AIC04、C03；H17/H22/H28。原契约换人不等取消，缺旧执行仍在途时写入及责任竞争。
- 权威/负责：workflows记录执行权代次、责任、剩余目标、交接/恢复；connections保存旧执行者原操作/停止/未知观察；AI只给配置依据；权限决定操作资格。
- 公开需求：请求暂停准入/接管、读取在途与剩余目标、记录新代次、按证据恢复；不能用暂停UI代替执行边界。旧操作观察必须可保存但不自动推进新工作。
- 收敛规则：接管阻新AI派发，执行权转移不证明旧执行终止；新代次拒旧代次权威写回，人工修改检查预期修订。旧结果为旧责任的历史观察，不能覆盖人工产物；未决外部操作继续占其冲突范围。恢复需要停止或独立核对证据、当前许可和新计划；不能凭“接管完成”显示可安全双写。
- 实验/影响：X06真库代次/CAS，两写者仅一成功，旧回执及失败竞争保留；停止证据是注入，不能约束外部直接写文件。WEX内部写权可先设计，外部Agent接管仍待真实取消/目录隔离/fencing验证。
- 候选/争议：执行权技术代次/fencing B/C；谁可强制解除unknown及损失承担D04，未代选。正式自动接管/恢复黄色。

## F07 产物版本与验收

- 来源/场景：W04/W06、C04、SP投影；H03/04/17/H26–28。原契约有版本失效，缺mtime伪同、同名、规则变更及历史验收适用性。
- 权威/负责：Requirement/Artifact登记/Verification/Acceptance均由workflows维护不同事实；真实文件在来源系统，connections观察真实定位/版本，shared仅保存；Review是意见，不代验证或最终采纳。
- 公开需求：登记产物的任务/执行轮次/规范定位/内容版本、独立核验并绑定输入/规则/产物版本、查询适用性、按有权主体记录Acceptance。外部地址先解析/鉴权/取证，不仅判断字符串或存在。
- 收敛规则：文件存在/退出0不完成任务；mtime/大小/名称不足当版本；内容变化、输入/规则变更使旧Verification不适用。移动可获权显式重定位后重新核验，不凭同名重绑；删除标缺失保留证据，失败产物不自动删除。旧版本验收保留历史，不能覆盖新版本当前适用性；自动验收政策未定。
- 实验/影响：X07真文件验证同mtime改内容、移动/删除/同名不同内容、Requirement修订/Verification失败；没有产物注册服务/真实Acceptance引擎。检查后再次写的TOCTOU、原子快照、来源归因和跨进程验收事务仍C。
- 候选/争议：哈希/快照实现B/C，Acceptance主体/自动范围D03、历史保留D05。可施工记录与版本适用性，不启自动最终验收。

## F08 安装/数据根与实例锁

- 来源/场景：APP01/03/04、SH01/03、Windows目录设计；H05/H10/H30。原契约分目录，缺应用单实例与根写权/业务锁分离证据。
- 权威/负责：app负责安装定位、可信安装/运行关系和迁移协调；shared负责根身份、技术锁/提交；领域负责业务数据迁移/恢复；runtime管理业务资源；permissions维护许可。不能由root锁隐含授权。
- 目录收敛：安装目录只放程序/受管静态资源；用户根放可控配置、索引、日志、缓存、数据库及两类插件包/状态；Space/Context可在其他自选工作区，关联不搬文件。系统凭证/注册与必要bootstrap定位为明确例外，记录实际路径，不能承诺C盘零写入。卸载默认保留数据，重装重配凭证/授权，正常重启不能等同重装。
- 锁收敛：Electron单实例、数据根排他写权、业务资源协调三分。未证协作写模式前不允许两个WEX写者同时打开同根；异根实例是否提供产品入口仍D，但不能误共享profile。锁文件存在/PID/时长不证明有效；持有者身份代次与OS活性/锁证据无法核对时阻写。异常退出OS锁释放不代表外部Operation停止。
- 实验/影响：X08 Linux合作进程flock同根拒/异根可得、强杀遗留文件可再锁、两进程仅一写与SQLite integrity通过。不是Windows锁/跨用户ACL/SMB/重解析点/根迁移验证，不能选择flock作Windows实现。
- 候选/争议：原生平台锁、规范根身份/迁移屏障B/C，跨用户共享写与强制夺锁政策不自行批准。Windows写根与迁移仍黄/红子能力。

## F09 桌面基础能力归属

- 来源/场景：基础能力遗漏审查、APP/SH/UI/CN/VW现有条款；H16/H19–21/H30。本批核对已有owner，不补造全局基础系统。
- 负责/公开需求：见下表；启动诊断/保存/关闭/恢复均消费各领域公开能力，app不重派Task，UI不造业务真相。

| 能力 | owner/权威数据 | 公开边界与范围 |
|---|---|---|
| 启动/退出/生命周期/进程/实例 | app；shared提供根锁 | 就绪/降级/退出协调/原代次诊断；关窗不等取消，后台D04 |
| 数据根/配置/缓存/数据库 | app定位；各域配置；shared技术存储 | 格式/容量/提交/回读/迁移屏障，非业务全局store |
| 日志/错误报告/诊断 | shared日志技术；app导出协调；各域事实 | 脱敏、丢失/截断/来源时点；日志不替代Operation/授权审计；清理D05 |
| 崩溃/恢复/重启 | app协调；领域各自恢复 | 先核对/只读诊断，unknown不重派；不得仅依赖退出钩子 |
| 系统通知/全局检索 | app系统承载，UI聚合，领域获准查询 | 通知只线索，点击重判；索引非可见性权威；敏感预览D05 |
| 安装/更新/卸载/保留 | app协调，领域格式/迁移，shared备份 | 程序版本与数据格式分开；默认留数据；自动更新不默开 |
| 凭证/注册/安装关系 | shared credentials技术、app可信关系、permissions许可 | 可解密不等有效授权；重装不静默恢复 |
| 环境/网络/健康检查 | app宿主偏好，connections实际支持/观察 | 配置保存不等连接成功；睡眠/代理恢复使旧健康过期，不自动重派 |

- 实验/结论：X09 Windows无环境、无产品EXE，实机未执行；X08与现有进程测试只补部分跨平台证据。通知/托盘/更新/系统凭证仍需E4，不能写通过。基础能力责任已明确，可开始诊断协议/装配替身，不能宣布安装恢复具备交付条件。
- 候选/争议：打包器/路径bootstrap/错误出口实现B/C；后台、自动更新、保留/敏感预览D04/D05。不新增顶层模块，不重复建设已有存储/权限/操作账本。
