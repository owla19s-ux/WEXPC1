# WEX 产品基础功能总表（首轮正式整理稿）

- 日期：2026-11-01
- 产品：WEX；当前工程主线：Windows PC
- 文档性质：完整产品基础功能需求基线的首轮整理稿；用于需求核对、模块契约对齐和后续版本推导。
- 当前状态：F01–F15 主骨架沿用；本稿细化基础业务能力，不代表所有 B/C/D 项已获用户批准，也不代表已实现。
- 版本规划：本稿不决定 0.1.1 的纳入范围、交付顺序或发布日期。

## 1. 文档目标与使用规则

本表回答：WEX 作为产品，必须具备哪些可独立调用、可组合、可持久化、可验证的基础能力；每项能力由谁拥有；它依赖什么；失败时如何表达；如何证明它成立。

本表不是页面清单，不是 UI 设计稿，也不是施工批次表。

### 1.1 需求状态与实现状态必须分开

| 标记 | 需求状态 | 含义 |
|---|---|---|
| A | 已确认 | 有明确产品方向、用户要求或稳定模块职责依据 |
| B | 候选细化 | 为使已有需求可实施而提出的能力拆分/规则建议，仍需评审 |
| C | 待实验 | 业务目标已识别，但可靠实现方式或关键假设需要真实实验 |
| D | 待用户决策 | 涉及产品政策、权限取舍、数据保留或重大体验选择，不能由施工者代定 |

另行记录实现状态：

- 已实现：当前产品源码中有对应能力，仍需按范围和环境验收。
- 实验/原型：有独立实验或原型，不等于产品实现。
- 已设计：有 README / CONTRACT / 研究文档，没有完整产品实现。
- 未设计：尚无足够业务规格。
- 待实机：有代码或实验，但目标 Windows 环境、真实外部服务或真实用户流程尚未验收。

**需求 A 不代表代码已实现；实验通过不自动把 B 升为 A；C 实验不能替代 D 用户决策。**

### 1.2 基础功能的定义

基础功能是可以脱离某个固定页面、某种工作模式、某个模型或某次对话而独立使用的业务能力。

例如：

- 创建一个 Context，是基础能力。
- 用户在 Space 页面点击“新建 Context”，是交互操作。
- 弹出对话框、树节点和保存按钮，是 UI 呈现。
- 保存成功后得到权威 Context 身份和修订，是基础能力的结果。

同理：

- 读取文件是基础能力。
- 用户拖入文件是交互方式。
- 文件选择器和附件卡片是 UI。
- 文件读取是否获权、来源版本是什么、结果如何保存，是业务契约。

基础能力必须可以由 UI、API、Agent、工作流或其他获准入口调用。不能因为没有页面就认为功能不存在，也不能因为页面按钮存在就认为底层功能已经实现。

### 1.3 单项功能规格的共同要求

每项基础能力在进入模块施工前，至少要明确：

1. 业务目的和适用对象。
2. 输入、输出和权威数据归属。
3. 正常行为与生命周期。
4. 前置条件和依赖能力。
5. 权限要求及可信调用入口。
6. 拒绝、失败、超时、取消、结果未知的语义。
7. 持久化、版本冲突、并发和恢复规则。
8. 可执行的正例、负例和异常验收条件。
9. UI 映射只记录关联，不在本表冻结页面和控件。

### 1.4 当前事实基线

以 WEXPCeasy 当前 main 文档为准：

- 产品技术路线为 TypeScript + Electron + React；Windows E4 尚未通过。

# 3. F01｜Space 与上下文组织

**目标：** 为个人工作、研究、创作和软件开发提供可自由组合的工作环境。Space 负责组织入口，Context 是可独立存在的工作环境；Context 不等同 Project，也不强制绑定模板、任务、Agent 或代码目录。

**权威 owner：** space。

| 功能 ID | 基础功能 | 业务行为与边界 | 依赖 | 最低验收条件 | 状态 |
|---|---|---|---|---|---|
| F01-001 | Space 类别管理 | 对 Space 进行类别组织；类别用于分类和入口，不自动绑定物理目录、账号、组织或权限 | 存储、space | 改变类别不改变 Context 身份、文件位置或权限 | B |
| F01-002 | Space 生命周期 | 创建、读取、修改、归档、恢复和删除 Space；删除 Space 不等于删除其引用的 Context | permissions、shared/storage | 归档/删除后核对引用目标仍存在；未获权不能修改 | A/B |
| F01-003 | 工作区与目录登记 | Space 可登记用户选择的工作区目录；登记与物理搬迁分开 | app、shared、local | 失盘时保留原引用并报告不可用，不创建同名空目录冒充恢复 | A |
| F01-004 | Group 组织 | Group 可选；支持创建、重命名、排序、移动和解除组织关系 | space | 无 Group 时 Space/Context 仍可独立工作；移动 Group 不迁移资料 | A/B |
| F01-005 | Context 独立创建 | 不依赖 Space、Group、Project、Template、Task 或 Agent 即可创建 Context | shared/storage | 创建独立 Context 后可读取、配置和再次打开，不自动创建其他对象 | A |
| F01-006 | Context 本体与配置 | 管理 Context 自身身份、名称、说明、定位和自身配置；不复制其他领域数据 | shared/storage | 修改名称不改变身份；配置修订可追踪 | A/B |
| F01-007 | Context 多处放置 | 同一 Context 可被多个 Space/Group 引用；每个引用位置独立管理 | space | A、B 两个 Space 指向同一本体；解除 A 不影响 B 和本体 | A |
| F01-008 | Context 组合引用 | Context 可关联资料、资源、角色、连接、能力、工作流和其他 Context | 各目标 owner、permissions | 关联只保存关系，不复制目标权威状态、不自动授权、不递归开放全部内容 | A |
| F01-009 | Context 有效配置解析 | 根据 Context 自身配置和明确关联，解析当前可用的组合结果；必须区分默认值、显式覆盖、冲突和不可用项 | AI、connections、workflows、permissions | 目标失效、配置冲突或权限不足时明确报告，不静默使用上次配置 | B/C |
| F01-010 | 引用解除与本体删除分离 | 解除放置、解除组合引用、删除 Context 是不同动作；删除须检查影响、授权和在途工作 | permissions、各目标 owner、workflows | 移除引用不删除目标；存在引用/在途工作或检查不完整时不得报告安全删除 | A/C/D |
| F01-011 | Context 查询与可见性 | 查询 Context、放置关系和获准的最小摘要；无权目标不得通过名称、数量或反向列表泄露 | permissions | 不同入口查询同一 Context 时分别判权；无权与不存在不得泄露存在性 | A/B |
| F01-012 | Context 接回与重定位 | 重新定位独立 Context 目录、识别目录身份冲突和失联；登记索引不成为第二份本体 | app、shared、local | 旧目录失联不新建同名空 Context；复制目录产生身份冲突时阻止自动合并 | C |

**本域不负责：** Agent 职责绑定、对话背景快照、Task 依赖、权限账本、文件正文、连接器调用和 UI 布局。

# 4. F02｜Agent 与角色体系

**目标：** 将 Agent 定义、角色、职责、运行实例和外部会话分开，使同一个 Agent/模型可以在不同工作范围承担不同职责，同时保持身份和授权隔离。

**权威 owner：** AI；角色配置就近归 AI/roles；外部 Agent 的实际运行事实归外部系统，WEX 只保存映射与可观察状态。

| 功能 ID | 基础功能 | 业务行为与边界 | 依赖 | 最低验收条件 | 状态 |
|---|---|---|---|---|---|
| F02-001 | Agent 定义 | 创建、读取、修改、归档 Agent 的基础定义；不要求 Agent 必须属于某个 Context | shared/storage | Agent 可独立存在；修改配置不改变历史执行身份 | A/B |
| F02-002 | 角色定义 | 定义秘书、主 AI、研究、执行、审查、验证等可扩展职责；角色名称不直接授予权限 | AI/roles、permissions | 改角色名称或描述不改变权限决定 | A |
| F02-003 | 职责配置 | 将角色/职责与 Agent 配置组合；允许同一主体承担多个职责 | space、permissions | 兼任职责不合并不同 Context 的资源授权 | A |
| F02-004 | 职责范围绑定 | 在 Context、Task 或其他明确工作范围内绑定职责；选择关系与实际任务分配分开 | space、workflows | 选择角色不自动生成 Task、不自动派发、不扩权 | A |
| F02-005 | 模型与连接引用 | Agent 配置可引用模型、Provider 或外部连接；不保存 Key/Token | connections/api、shared/credentials | 替换模型连接不改写历史调用和在途任务依据 | A/B |
| F02-006 | Agent 配置修订 | 管理 Prompt、偏好、职责、模型引用等配置版本；新工作绑定明确修订 | shared/storage | 更新配置后，旧任务仍可追溯当时配置 | B |
| F02-007 | Agent 实例生命周期 | 创建、启动、观察、暂停、恢复、释放 WEX 可管理的 Agent 实例；不强制自建完整 Agent Runtime | app、connections | 实例状态与 Agent 定义分开；释放失败保留可重试诊断 | B/C |
| F02-008 | Agent Session 映射 | 保存 WEX 任务/执行与外部 Agent Session 的映射；Session ID 不是主体身份或权限凭证 | connections/dsh 等 | 外部 Session 丢失或不可查询时保留未知，不伪造恢复成功 | A/B |
| F02-009 | 外部 Agent 接入 | 将任务交给独立 DSH/Hermes 等外部客户端；WEX 不搬运其内部循环和会话结构 | connections 对应适配器 | 外部 Agent 只报告实际可观察能力；不支持的取消/恢复不假装支持 | A |
| F02-010 | 执行者替换与交接 | 任务可更换执行者，保留旧执行者、旧轮次和已有证据 | workflows、connections | 更换 Agent 不删除旧结果、不重复执行未知副作用 | A/B |
| F02-011 | Agent 记忆策略配置 | 为 Agent 声明独立、Context 共享、角色共享等记忆范围；共享开关不等于共享权限 | F10、permissions | 关闭共享后不再向该范围读取；不自动删除来源 owner 的原始数据 | B/D |
| F02-012 | Agent 状态与工作状态分离 | Agent 在线/离线、配置有效、Session 可查询，与 Task 状态分别维护 | connections、workflows | Agent 离线不自动将 Task 标记失败；Task 完成不证明 Agent 仍在线 | A |

**本域不负责：** Provider 协议、API Key、Task 状态、操作账本、资源锁、授权政策和 UI 角色动画。

# 5. F03｜对话系统

**目标：** 提供独立于 Project、Task、Template 和 Agent 团队的原生对话能力，并支持细粒度消息交互、来源追踪、工具往返和跨会话恢复。

**权威 owner：** conversations。

| 功能 ID | 基础功能 | 业务行为与边界 | 依赖 | 最低验收条件 | 状态 |
|---|---|---|---|---|---|
| F03-001 | 独立会话生命周期 | 创建、读取、重命名、归档、恢复和删除 Conversation；Context/Task 可空 | shared、permissions | 无 Space/Context/Task 仍可普通聊天并保存历史 | A |
| F03-002 | 消息与轮次持久化 | 保存用户输入、模型回复、消息来源、逻辑生成和版本关系 | connections/api、shared | 断网/重启后能区分已保存、未保存和提交未知 | A/B |
| F03-003 | 消息序列项 | 将一轮回复拆成有稳定身份的有序项，支持独立引用和状态记录 | UI 后续映射 | 序列项 ID 稳定，不因重新渲染或排序变化而改变 | A/B |
| F03-004 | 局部选择与引用 | 选中消息、段落或序列项并作为后续输入依据；引用不等于采纳或执行 | permissions、source owner | 引用历史版本后，原消息修改不改变引用来源 | A |
| F03-005 | 分支讨论 | 对选中内容开启独立讨论分支，保留来源和回链 | conversations | 分支结论不静默覆盖主线或已确认内容 | A/B |
| F03-006 | 已发送消息修改与重发 | 编辑历史输入并创建新逻辑生成；保留旧生成与其外部副作用 | connections、permissions | 含写文件工具的旧回复被重发时，不自动重做旧副作用 | A |
| F03-007 | 生成期间追加与排队 | 当前生成进行中可追加输入；已派发输入快照不可原地修改 | connections/api | 追加内容明确进入后续队列，不暗改当前生成输入 | A |
| F03-008 | 流式输出与定稿 | 接收流式片段，区分暂态片段、已保存消息和正式定稿 | connections/api、shared | 乱序/重复片段不生成多份定稿；断流不显示为完整成功 | B/C |
| F03-009 | 停止生成 | 停止等待、停止显示、请求远端取消、确认外部停止分别表达 | connections | 点击停止不等于外部已停止；迟到结果仍归原生成 | A/C |
| F03-010 | 对话背景与模型选择 | 保存当前会话选用的 Context、Agent/角色、模型等关系；每轮生成固定输入快照 | space、AI、F04 | 切换背景不改写已派发生成所用的来源 | A/B |
| F03-011 | 输入附件与来源 | 接收文本、文件、图片等输入引用，保留来源、版本和授权依据 | connections/local、space、permissions | 临时附件不自动成为 Context 长期资料；导入与引用原文件区分 | A/B |
| F03-012 | 工具意图往返 | 识别模型结构化工具意图，经过授权和连接边界执行，再把真实结果回注模型 | F04、F05、F09 | 模型文本中出现命令不自动执行；拒绝/未知结果准确回注 | A/B |
| F03-013 | 显式转为 Task | 用户或获准规则明确将内容转为正式 Task；普通对话不自动成为任务 | workflows、permissions | 同一转任务请求只创建一次 Task；失败不标记已创建 | A |
| F03-014 | 会话检索与历史读取 | 查询会话、消息、序列项和来源引用；读取时重新判权 | permissions、views | 撤权后旧缓存不能继续显示受限正文 | B |

**本域不负责：** Provider 协议、Operation 权威账本、Task 检查点、工具权限和最终验收。

# 6. F04｜模型系统

**目标：** 将用户目标变成可分配、可推进、可并发、可恢复的持续工作。必须区分 Task、Workflow、Execution、Operation、外部 Session 和实际资源状态。

| 功能 ID | 基础功能 | 业务行为与边界 | 依赖 | 最低验收条件 | 状态 |

| F08-002 | Task 修订 | 修改目标、范围、优先级和验收条件；变更保留历史 | shared、permissions | 在途任务绑定原修订；范围变更需显式产生新依据 | A/B |

| F08-004 | 工作轮次 | 记录执行、返工、审查和重新分配的独立轮次 | connections、F13 | 返工保留旧轮次及其 Operation/证据 | A |
| F08-005 | 任务队列与优先级 | 管理等待、就绪、排队、阻塞和调度顺序 | runtime | 排队不代表已授权或已派发 | B |
| F08-006 | 依赖与条件推进 | 判断前置 Task/步骤/资源条件是否满足 | workflows、connections | 依赖未满足时不派发；状态变化有来源依据 | A/B |
| F08-007 | 执行者选择与路由 | 按任务要求、能力、连接可用性和职责选择候选执行者 | AI、connections | 能力不支持或连接不可用时明确阻塞 | A/B |
| F08-008 | 调度与派发 | 在权限、资源、版本和依赖复核后请求连接边界派发 | permissions、connections | 派发前 attempt 保存失败则外部调用为 0 | A |

| F08-010 | 并发与容量调度 | 管理并发上限、执行资源和可用能力配额 | app、connections | 并发超限明确排队；不能静默覆盖资源 | B/C |
| F08-011 | Task 状态与推进 | 管理创建、就绪、运行、阻塞、待审查、返工、完成等业务状态 | connections、F13 | 不把 Operation completed 直接写成 Task completed | A |
| F08-012 | 暂停、继续和停止 | 分别处理未派发排队项、已派发操作和 Task 工作状态 | connections、permissions | 关闭窗口不自动取消 Task；请求停止不等于已停止 | A |
| F08-013 | 失败、重试与升级 | 区分可修复、阻塞、最终失败、未知和需用户裁决 | connections、F13 | 未知副作用不盲重试；重试保留原尝试 | A |
| F08-014 | 检查点与跨会话接续 | 保存目标、范围、轮次、输入引用、Operation 引用、产物、阻塞和下一步 | F10、F13、connections | 新对话/新 Agent 能核对事实后接续，不依赖旧模型隐藏上下文 | A |
| F08-015 | 人工接管与交接 | 用户可接管、修改验收、替换 Agent 或重新分派 | AI、permissions、connections | 旧执行者迟到结果仍归原轮次，不覆盖新轮次 | A/B |
| F08-016 | 持续推进策略 | 在用户授权范围内连续推进，不要求每一步重新催促；不默认关机后后台运行 | app、permissions | 已授权范围内可连续推进；新范围/高风险动作仍按策略确认 | A/D |

**必须保持的对象区分：**

- Workflow：流程定义。
- Task：目标与业务工作状态。
- Execution：一次运行过程。
- Operation：一次真实外部调用及其观察。
- Receipt：执行方/外部系统回执。
- Result：产生的结果。
- Evidence：可用于核验的证据。
- Verification：是否符合指定检查标准。
- Acceptance：是否正式接受该结果。

**目标：** 使 WEX 能长期运行、观察、诊断和维护。日志、Operation、权限审计、Task 证据是不同业务事实，不得用统一日志替代各自账本。

**权威 owner：** app/shared 提供技术保障；connections、permissions、workflows 各自拥有领域运行记录。

| 功能 ID | 基础功能 | 业务行为与边界 | 依赖 | 最低验收条件 | 状态 |
|---|---|---|---|---|---|

| F15-002 | 跨模块调用追踪 | 关联一次用户请求、Task、Execution、Operation、回执和验证 | 各 owner | 关联标识不替代各领域权威状态 | B |
| F15-003 | 运行指标 | 记录进程资源、存储容量、连接延迟和调用用量等 | app、connections、shared | 指标口径和来源明确；未知数据不伪造精确值 | B |
| F15-004 | 健康检查 | 汇总应用、模块、连接器和依赖的就绪状态 | app、各 owner | 一个连接器失效不阻断无关普通对话；降级范围清晰 | A/B |

## 18. 横向基础机制：归属与限制

以下机制横跨多个功能域，但不因此自动成为新顶层模块。

| 横向机制 | 业务事实 owner | 技术支持 owner | 不允许的做法 |
|---|---|---|---|
| 对象身份与关系 | 各对象所属模块 | shared 提供必要技术原语 | 全局 Resource Center 接管所有业务对象 |
| 资源定位与引用 | 实际资源 owner；space 保存组合引用 | connections/local、shared | 把路径当永久身份或把引用当授权 |
| 配置 | 各模块拥有自己的配置语义 | shared 可提供通用存储/迁移技术 | 建万能全局配置中心解释所有业务字段 |
| 事件与通知 | 事件所属业务模块 | app/shared 提供必要传递技术 | 让事件总线成为第二份权威状态 |
| 搜索 | 各业务 owner 提供获准查询 | UI 聚合；必要时 shared 提供索引技术 | 用全局搜索绕过模块权限或建立内容权威副本 |
| 凭证 | shared/credentials 保管秘密 | app 提供平台安全存储接线 | 将 Key 放进普通配置、日志或 Agent Prompt |
| 日志与审计 | connections / permissions / workflows 各自维护正式事实 | shared logging/diagnostics、app 装配 | 普通日志轮转删除业务账本 |
| 调度与占用 | workflows/runtime 管任务及 WEX 占用；connections 管 Operation | app 装配和传递 | 连接器私自管理 Task，或工作流复制 Operation 状态 |
| 资源数据 | 文件/远端系统的实际 owner | local/GitHub/API 适配器 | 视图、Task 或 Artifact 成为文件内容第二权威 |
| 视图布局 | views | UI 呈现 | 将坐标、画布连线当作业务关系、权限或执行事实 |

## 19. 全产品必须遵守的基础不变量

1. **唯一权威 owner：** 一个业务事实只有一个正式维护者；其他模块通过引用、查询、事件或受控调用协作。
2. **关联不等于授权：** Space/Context 关联、角色选择、连接发现、模板启用、Task 分配都不自动授予资源权限。
3. **角色不等于身份：** Agent 定义、角色职责、Actor 身份、模型、Session、权限分开。
4. **连接不等于能力可用：** 连接已配置、能力已发现、环境就绪、授权允许、操作已执行、结果已验证是不同状态。
5. **对话不等于任务：** 普通聊天和单次工具调用可以没有 Context、Task 或 Workflow。
6. **任务不等于操作：** Task 维护业务目标和进度；Operation 维护一次真实调用和观察。
7. **结果未知不是失败：** 超时、断连、回执保存失败不能推断外部副作用未发生。
8. **取消不等于回滚：** 请求停止、确认停止、补偿和删除是不同动作。
9. **证据绑定版本：** 文件/Commit/产物变化后，旧 Verification 不能自动证明新版本。
10. **视图不拥有业务事实：** 树、画布、表格、列表、看板均为权威对象的投影。
11. **配置归 owner：** 各模块维护自身配置含义；shared 不成为业务配置总管。
12. **数据与凭证分离：** 普通资料可以重新接回，敏感凭证和有效授权不得在系统重装/卸载重装后自动恢复。
13. **外部 Agent 独立：** DSH/Hermes 的内部会话、Agent Loop 和权限由其自身系统拥有；WEX 只维护受控交接、观察和验收。
14. **插件体系分离：** WEX Plugin、Connector、Template、Module、DSH 原生插件、外部 DSH Agent 不是同一对象。
15. **UI 不是底层实现：** UI 可以组合调用能力，但不能成为唯一业务入口、事实来源或权限边界。
