## 规格层级

1. **F：基础功能规格**——定义系统能力、业务规则、数据归属和验收条件。
2. **I：交互语义规格**——定义用户、Agent、API、工作流等入口提出的业务意图。
3. **U：UI 呈现规格**——定义页面、控件、导航、拖放、快捷键、语音和视觉状态；后置设计。
4. **V：版本规格**——从完整 F 功能中筛选版本范围；必须在产品需求评审之后建立。
5. **T：施工任务规格**——依据确认的版本和模块依赖拆分施工批次与验收。

F/I/U/V/T 不得混为一张表。页面按钮不等于基础能力；功能编号不因 UI 改版而改变。

## 需求状态与实现状态

需求状态使用 A/B/C/D：
- A：已确认。
- B：候选细化，仍需评审。
- C：需要实验。
- D：需要用户决策。

实现状态另行记录：已实现、实验/原型、已设计、未设计、待 Windows/真实外部实机验证。

**写入本目录不代表所有 B/C/D 需求已批准，也不代表产品代码已实现。**

## 维护规则

- 本目录维护产品级功能范围与跨域审查；各模块的具体业务行为仍以对应 README/CONTRACT 为准。
- 功能编号稳定，不因模块目录调整或 UI 页面变化而重新编号。
- 修改业务 owner、权限边界或对象语义时，必须同步模块契约并复查复杂链路。
- 不将 H01–H30 复杂业务链路拆成跨模块施工单位；它们用于发现遗漏和组合验收。
- 不从本目录直接推导 0.1.1 范围。必须先完成需求评审和用户待决项处理。
- 不因本目录建立而提前新增顶层源码模块、协议、数据库表或 UI 页面。
