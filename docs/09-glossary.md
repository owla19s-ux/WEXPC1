# 09 — 术语表

> 同名不同义是本项目最大的沟通成本来源。本文固定本仓用词；与产品文档冲突时，以产品文档为准，并在此注明差异。

## 1. 组织与工作对象

| 术语 | 英文 | 含义 | 不是什么 |
|---|---|---|---|
| 空间 | Space | 用户可见的工作组织入口 | 不是磁盘路径，不是权限边界 |
| 分组 | Group | Space 内的可选组织方式 | 不是必选层级，不是所有权 |
| 上下文 | Context | 一个工作域/工作范围，可引用对话、Agent、任务、资源、连接、其他 Context | 不是 Project 的改名；不是强制所有者；不是权限来源 |
| 工作对象 | Work Object | 可被引用/关联的实体（对话、任务、资源、记录等） | 不是必须属于某个 Context |
| 资源 | Resource | 被访问/修改/产生的实际对象 | 不是地址，不是权限 |
| 地址 | Address | 指向资源位置的记录（名称/地址/备注） | 不是资源本身，不是授权 |
| 项目 | Project | Context 的一种使用方式（可选） | 不是顶层万能对象 |

## 2. 连接与能力

| 术语 | 英文 | 含义 | 不是什么 |
|---|---|---|---|
| 连接 | Connection | 某个服务/端点/身份的配置与连接状态 | 不是连接器实现，不是权限 |
| 连接器 | Connector | 实现与外部能力源交互的组件 | 不等于 Connection；不等于模块（可以是一个模块的一部分） |
| 能力 | Capability | 能做什么、输入输出、限制、可用状态 | 不是权限，不是模块 |
| 工具 | Tool | 能力的可调用暴露形式（尤其对 AI） | 不是所有能力都必须暴露为工具 |
| 提供者 | Provider | 能力的来源类型（内置模块、SDK、MCP、外部服务等） | 不是权限主体 |
| 能力声明 | Capability Descriptor | 描述能力的结构化数据 | 不是授权，不是实现 |

## 3. 执行与证据

| 术语 | 英文 | 含义 | 不是什么 |
|---|---|---|---|
| 调用 | Invocation | 一次具体的“请求执行某能力”的信封 | 不是任务，不是审批 |
| 操作 | Operation | 一次有身份、有状态、可追踪的执行意图 | 不是 Task；Task 是可选的	work 组织 |
| 尝试 | Attempt | 操作的某一次实际执行 | 不是新操作 |
| 回执 | Receipt | 外部系统返回的执行事实/标识 | 不是验证通过 |
| 证据 | Evidence | 支持核验的实际记录（SHA、日志、产物、回读） | 不是 AI 自述 |
| 验证 | Verification | 依据证据判断目标是否达成 | 不是执行成功 |
| 结果未知 | Outcome Unknown | 有副作用但无法确认结果 | 不是普通错误，禁止自动重试 |
| 账本 | Ledger | 追加式记录操作/尝试/回执/证据 | 不是业务状态机，不是审计日志的全部 |

## 4. 协作与角色

| 术语 | 英文 | 含义 | 不是什么 |
|---|---|---|---|
| 主体 | Actor | 发起操作的身份（人/AI/服务） | 不是模型，不是角色 |
| 角色 | Role | 职责定义（主 AI、施工、审查、秘书等是可配置职责） | 不是固定 AI 类型，不是权限 |
| 分配 | Assignment | 主体在某个范围内承担某角色的关系 | 不是授权 |
| 会话 | Session | 一次持续交互/执行的运行上下文 | 不等于 Conversation |
| 模型 | Model | AI 服务提供的具体模型 | 不等于 Connection，不等于 Role |
| 工作流模板 | Workflow Template | 可编辑的配置，组合能力/角色/资源/工序 | 不是执行引擎，不是脚本 |
| 工作流实例 | Workflow Run | 模板版本快照 + 变量绑定 + 运行状态 | 不是模板本身 |

## 5. 工程结构

| 术语 | 英文 | 含义 | 不是什么 |
|---|---|---|---|
| 模块 | Module | 源码维护单元，拥有完整功能 | 不是进程，不是插件 |
| 公共机制 | Platform Mechanism | 多模块共享、语义一致的机制 | 不是业务模块，不是 core |
| 契约 | Contract | 跨模块稳定接口与数据 | 不是实现，不是文档 |
| 组合根 | Composition Root | 唯一装配全部模块的地方 | 不是业务层 |
| 宿主 | Host | 平台适配与运行载体（Windows/Tauri） | 不是业务模块 |
| 扩展 | Extension | 模块的隔离/可替换/交付属性 | 不是与 Module 并列的功能体系 |
| 插件 | Plugin | 未来的动态加载形态 | 现在不做 |

## 6. 容易混淆的对

| A | B | 区别 |
|---|---|---|
| Module | Plugin | 前者是源码维护单元；后者是动态加载/第三方分发形态 |
| Connection | Connector | 前者是运行时配置/状态；后者是实现组件 |
| Capability | Permission | 前者是“能做什么”；后者是“谁在什么条件下可以做” |
| Operation | Task | 前者是一次执行；后者是可选的工作组织 |
| Receipt | Verification | 前者是执行事实；后者是目标是否达成 |
| Context | Project | 前者是工作域；后者是 Context 的一种使用方式 |
| Role | Assignment | 前者是职责定义；后者是“谁承担这个职责” |
| Template | Run | 前者是配置；后者是带版本快照的运行实例 |
| Space | Directory | 前者是用户组织入口；后者不是必须存在的底层层级 |

## 7. 本仓新增的工程用词

这些词只用于工程规范，不是产品运行时概念：

- **能力声明（Descriptor）**：能力的结构化描述数据。
- **公共机制（Mechanism）**：多模块共享的实现。
- **组合根（Composition Root）**：装配点。
- **中央文件预算**：新增功能允许修改的中央文件数上限。
- **护栏（Guardrail）**：CI/工具/检查清单。
- **局部性实验**：验证新增功能是否局部完成的实验。

## 8. 命名约定

- 模块 ID：小写连字符（`github`、`ai-api`、`local-files`）。
- 能力 ID：`<module>.<resource>.<action>`（`github.issue.create`）。
- 事件：过去式（`OperationCompleted`）。
- 状态：名词（`InFlight`、`OutcomeUnknown`）。
- 不要用：`core`、`common`、`utils`、`helpers`、`manager`、`service`（作为模块名会吸走无法归类的代码）。
