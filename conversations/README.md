# conversations — 独立对话与生成业务

状态：职责设计，尚无产品实现。维护 Conversation、消息、段落选择/引用、追加、修改重发与分支；普通对话无需先创建 Space、Context、工作流或 Task。

- 会话维护“本次使用哪个 Context 作为背景”的关系；Context 中显示某会话的引用是另一个组织关系，归 `space`。若产品将二者定义为同一关系，只允许一个维护方，不能双写。
- 会话负责一轮输入、生成关联及最终消息的保存；`connections/api` 负责真实 Provider 调用、流式协议和操作回执。一次逻辑生成可关联多次外部尝试，聊天消息不冒充调用账本。
- 用户段落勾选/采纳、AI 提议、正式任务创建、工具授权和最终验收是不同动作。生成任务时经 `workflows` 的业务入口；模型工具提议经受控连接边界，不从渲染文本直接执行。
- 切换背景或编辑旧消息不修改已派发工作的输入事实，不默认取消或重做外部副作用；旧回复和回执保留来源，迟到结果不覆盖新的生成。恢复先查已知回执，不能“重新发消息”替代恢复。
- UI 归 `UI/conversation`；提示可见不等于可读全部 Context。取数、向外部模型发送资料和实际工具动作分别受适用授权限制。

逻辑轮次与外部调用分离可进入下一阶段业务契约；流式保存、取消竞态、重发/追加及重启恢复须再做窄实验，未确定实现接口。

## 第三批：模块契约设计入口（研究建议）

覆盖样本 L05。以消息/段落/生成的业务条件和外部尝试关联制定契约，背景查询和模型调用作为窄依赖。独立测试覆盖无 Task/Context、重发、断流、迟到和保存失败；替身不得让未知工具副作用被重新执行。

契约就近、公开出口/依赖约束、分层测试和模块施工方法见[统一研究](../docs/WEXPC-GLOBAL-CONTRACT-MAP-V0.1.md)。本段只给制定契约的依据，不表示公开接口已实现或所有建议已获采纳。
