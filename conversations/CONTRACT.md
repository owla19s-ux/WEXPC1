## 边界与证据

owner：Conversation、消息/段落的持久版本、会话选择背景的关系、逻辑生成及其与外部尝试的关联。普通聊天的 Context 与 Task 均可空。非职责：Provider 协议、外部 attempt/回执权威归 connections；Task 与验收归 workflows；Context 本体/放置归 space；授权归 permissions；流式 UI 缓冲不等于已保存消息。

## 公开能力与可验行为

所有调用由可信宿主识别主体及入口，模型自报角色/Context 不能作为主体。会话读取先判入口与目标可见性；无权与不存在对无权消费者采用同等不可用响应，不返回标题、段落数、历史、定位或存在性。资源读取、对外发送资料、工具执行是分别授权的动作。

所有持久变更区分**确定未提交、确认提交、提交未知**，这些是证据语义而非冻结枚举。只有 owner 能证明未提交时才显示未保存并允许按其规则重试；确认提交依据 ACK 或原业务关联回读；ACK 丢失/保存响应超时显示待核对，不推断未提交、不重写或补偿删改。查不到但索引/存储仍不可用也不能证明未提交。输入/定稿/引用/队列/采纳均遵守；未知输入提交不得另建生成或启动第二次派发。

|---|---|---|

| 接收流式片段并定稿：UI 显示暂态；宿主关联回执形成消息 | 仅接受已绑定本次逻辑生成/attempt 的可信来源；UI 临时序列标明暂态。最终消息须确认 conversations 提交，保留生成、来源版本及回执引用；片段不能直接产生工具动作 | 乱序/重复片段按来源定位处理；断流展示部分且未定稿。确定定稿未提交可按原关联重试保存；提交未知显示待核对，先查定稿提交事实，再查原回执/可用片段，不重写、不重调模型。G1 迟到不得覆盖当前 G2。断言：定稿已提交但 ACK 丢失，UI 待核对，回读确认一份定稿且只有一次提交，无补偿删除 |

## 最小依赖、私有实现与通知

space 仅提供获准背景引用/定位与关系修订，实际资料正文、版本和传播限制由其内容owner或对应资源适配能力提供；permissions 提供当前入口/目标/对外发送/动作判定及撤权依据；connections 提供受控调用、取消请求、按关联查询尝试/回执及未知分类，不能要求 conversations 解释厂商 session；workflows 提供显式任务创建/按关联核对；shared 提供领域可验证的保存/恢复结果。消费者不得深读这些模块目录。

私有：输入快照、片段缓冲、逻辑生成关联与持久化策略。app 注入窄依赖；UI 订阅只获准的消息/生成变化。通知可重放、重复、丢失，接收方按来源与修订回读，不将通知当权威写入；取消订阅不取消调用。

施工仍在 conversations，必要 UI 位于 UI/conversation；就近添加公开出口、实现、替身与测试，不预建包/全局事件总线。connections 持有 Provider 适配。不得把实验编辑器 Draft 或 connection attempt 状态复制到消息模型。

## 双方替身、集成门槛与准备度

消费者侧替身应可注入晚到 G1、重复片段、未知回执、保存失败、撤权；断言 UI 不将片段当定稿、不重派未知工具。提供方侧用同一行为样例检查真实 conversations：无背景输入、重复提交、版本冲突、定稿保存失败与恢复。connections 替身必须区分“确认未派发”和“可能已产生副作用”，不得总是返回成功/可重试。其提供方测试须证明原关联查询和取消证据语义；permissions 替身及提供方共同验证禁止取数与存在性遮蔽。

最小组合验收：真实持久化 + conversations + 连接边界，注入“输入已保存/派发前崩溃”“外部完成/关联未保存”“取消/定稿同时到达”，重启检查一个逻辑生成、可追溯多尝试、没有重复副作用。再验撤权、跨窗口修订及工具资源冲突。完成证据必须列基线、环境、实际命令、观察到的尝试数/持久消息/资源版本及未覆盖项；本批只静态读取和文档检查，未运行上述测试。

### 输入、定稿与工具提议：衍生内容和跨入口使用（F03/F07）

建议输入快照及生成关联保留获准来源、资料版本、范围限制和已发送目标依据；来源信息由实际owner提供且其访问本身受控，不能信模型输出补造来源。生成文本、引用片段、摘要与附件可能包含原资料，定稿保存成功不将其自动公开。向另一Context采纳/发给外部Agent或不同API、转Task及工具参数使用分别重新核对读取/披露/外发动作；不把完整历史默认塞入新的外部session。

外部内容存为内容/来源观察，不把其“允许调用工具”文本变成可信授权。未知来源/混合受限资料按permissions明确限制处理，不声称已实现自动敏感内容识别。原资料外部变更后历史输入保留原版本，下一生成重新取当前获准依据；必要版本不可得则明确证据不足。

断言：可向M发X的生成G，拿G摘要向N发仍需相应外发许可；G正文中的伪造内部身份不会触发工具；人工接管改写文件不会被写成模型已产出的消息事实。普通无Task对话仍能保存/读回受限来源，不制造工作流依赖。

## G1/G2/G5/G7 与跨对话持续工作补充（2026-10-31）

本节把基础输入、原生 API 工具往返、会话检索和跨对话恢复要求归回本域；跨域 owner 与验收矩阵见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

**G2：普通 API 工具往返。** Conversations 拥有一轮逻辑生成及其输入/输出关联；API 适配器只负责 Provider 请求、流式解析和厂商工具意图格式。最小流程为：持久化输入与生成关联 → 请求模型 → 接收普通内容或结构化工具意图 → 对每个工具意图请求 permissions 当前判定 → 由 connections 受控边界记录 Operation 并执行 → 将获准结果关联回同一逻辑生成 → 决定继续请求模型或定稿。模型文本/JSON 中出现的工具名称不等于已执行；Renderer 不直接执行；外部 Agent 的内部循环仍由其自身连接器管理。

一次逻辑生成可有 0..N 个外部尝试；每个真实副作用调用引用独立 Operation。普通对话不强制创建 Space、Context、Task 或 Workflow。工具被拒绝、不可用、结果未知或结果保存失败时，必须把真实情况反馈给本轮；unknown 不得通过重发整条消息来恢复。

**G1/G7：附件与输入快照。** 输入可包含文本、用户选择/拖入/粘贴的文件或图片等附件引用。会话保存本次输入实际采用的来源引用、必要的版本/内容快照依据及授权范围；临时附件不会自动成为 Context 长期资料。用户显式选择“加入 Context/持久保存”时，交给 Space 与受控资源能力建立长期关联；“引用原文件”与“导入持久副本”必须是可区分动作。附件字节和真实路径不由消息 JSON 随意复制，具体传输/存储协议待实现契约决定。

生成输入一经派发即形成不可变的本轮依据；切换 Context、修改消息或更换模型不会改写旧输入/旧 Operation。新一轮重新读取当前获准资源版本；旧来源无法读取时明确标示，不用私有缓存冒充最新资料。

**G5：会话检索。** 本域提供获准的会话、消息、段落和来源引用查询；不建立跨域全文搜索总库。列表/摘要/命中结果按当前主体和入口过滤，打开历史或附件时重新判权，撤权后不从旧缓存泄露正文。

**跨对话边界。** 新对话可以读取既有会话历史、Context 资料和 Task 检查点引用，但不能恢复模型隐藏上下文、旧流式缓冲或声称原逻辑生成仍在运行。恢复 Task 由 Workflows 决定；恢复外部调用由 Connections 查询原 Operation。Conversation 只提供历史与输入来源，不把对话总结当作 Task 权威检查点。
