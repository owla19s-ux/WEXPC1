# permissions — 策略、授权决定与撤权

状态：第二批架构细化；尚无产品授权引擎。此处是唯一的权限业务域；[shared/permissions](../shared/permissions/README.md) 仅保留旧入口指引，不再承担另一套授权服务。

## 判断什么

用户的明确授权、当前执行主体与入口、适用职责、Context/任务范围、目标资源及动作共同约束请求。保留“模块启用 / 全局访问 / 对话启用”三层依据；独立聊天/非对话任务也必须具有适用于自身入口的范围，不能伪造一个对话标识绕过检查。非对话入口如何对应既有范围，留给业务契约细化。

组织关系不产生授权：多个 Space 引用同一 Context、角色跨 Context 兼任、任务分配、工具可发现、模板启用、同一个模型或外部账号，都不能自动扩权。职责描述与授权分别维护，不按角色名称设超级管理员。不存在隐含跨入口权限并集。

## 谁负责检查与记录

- `permissions` 维护策略、授权/审批/撤销事实及判定依据；不持有角色定义、任务真相或凭证秘密。
- `connections` 的宿主受控调用边界调用此域检查对外请求和外部回调，关联判定依据与操作回执；具体连接器不能自行批准或修改授权记录。
- 内部领域正式入口保护自身写入规则与适用授权；普通内部调用不必全绕连接层。外部能力已过准入仍不允许绕过目标领域的修订/范围检查。
- 真实资源/进程执行边界落实可兑现的限制；排队前判断不能代替执行前复核。撤权后阻止新的数据提供与调用，处置在途工作的责任由执行方承担，工作流记录其后果。
- 授权记录与操作记录分别归本域与 `connections`，通过可追溯引用/当时依据关联，不复制第二套可修改的权限账本。具体持久化格式、求值算法和审计接口未定。

## 外部执行与安全极限

[app](../app/README.md) 负责受信任装配与可用的进程隔离；外部 Agent 受其实际 OS/服务权限约束。WEX 不提供 Key/文件就能控制后续 WEX 出口，但不能据此保证已有广权限的外部 Agent 被限制。无法约束的权限要显式暴露，不能声称“任务范围就是系统沙箱”。

第三方插件不能直接进入 Electron 主进程；独立进程本身也不是完整安全沙箱。插件/Agent 的返回文本是外部输入，不是授权或验收命令。停止本地等待、取消请求、撤权、外部已停止和副作用已回滚分别记录；不承诺模型遗忘或远端数据删除。

账号域 `accounts` 仍预留，不将远端登录作为本地授权前置；凭证保管归 `shared/credentials`。本批不设计完整账号平台、RBAC/ABAC 或插件沙箱。

待实验：Windows 实际权限收敛、外部凭证/环境传递、撤权竞态、插件回调身份与重放防护、跨进程终止及残留进程。场景 S7 的业务拒绝已有替身测试，未证明 OS 隔离。

## 第三批：模块契约设计入口（研究建议）

覆盖样本 L02–L12。公开判定/审批/撤销的行为前提应明确可信事实来源、范围、强制拒绝和在途限制；策略与审计实现保持私有。不通过导入全部领域数据库完成权限判断。用伪造入口、兼任、撤权与边界不可用样例检验，真实 OS/外部隔离仍另验。

契约就近、公开出口/依赖约束、分层测试和模块施工方法见[统一研究](../docs/WEXPC-GLOBAL-CONTRACT-MAP-V0.1.md)。本段只给制定契约的依据，不表示公开接口已实现或所有建议已获采纳。
