# AI/roles — 角色配置与职责关联

状态：架构责任已细化，产品代码未实现。维护角色名称、说明、提示/模型连接选择，以及角色或执行主体在特定工作范围内承担的职责；不保存任务执行状态或授权账本。

主 AI、秘书/管家、执行、审查是职责，不是不可兼任的固定等级。同一主体可以在不同 Context 中兼任，但每次工作使用适用的职责和授权范围，不能把各项目权限拼接。角色默认意图不能覆盖用户约束、强制拒绝或目标资源授权。

- `space` 的“选择这个角色”是组合关系；本目录的“在此范围担任审查”等是职责关系，含义不同。若未来产品将两者合为一个动作，仍须指定单一写入口，另一侧查询显示。
- 任务分配和执行尝试归 `workflows`，只引用职责与执行身份；任务分配不会修改全局角色模板，也不会产生新授权。
- 提示或职责变更不静默改写在途尝试的身份与输入；新工作采用哪个配置版本、在途工作如何调整，须显式判定并保留来源，具体版本/事件协议未定。
- 秘书默认不因名称获得写权限；审查只读与追加审查意见、执行者写文件等动作分别授权。实际有效权限由 [permissions](../../permissions/README.md) 决定。
