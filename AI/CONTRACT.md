# AI（含 roles）业务契约（第四批设计稿）

## A：owner 与非职责

AI/roles 唯一维护可复用AI/角色配置（名称、说明、提示、模型/连接选择）与特定范围内职责关联。主、秘书、执行、审查是可兼任职责，不是固定权限等级。Space选择角色由space维护，会话背景/生成由conversations维护，任务分配由workflows维护，授权由permissions维护。连接/Provider调用、Key和外部Agent循环/Session不属AI。首期简单配置不隐含内部自主循环、长期记忆或公共策略平台。

换模型不换执行身份、不改授权；职责/提示变更不静默改写在途输入，兼任不汇总各范围许可。模型已经看到的信息不因撤权遗忘。

## B：共同请求与观察语义

以下是业务信息，不要求固定字段名。可信调用事实必须由宿主绑定：当前主体（实际执行身份及来源）、入口（本地交互/独立对话/任务/受控回调的实际实例与代次）、适用职责事实及其来源修订、目标资源身份与动作。外部文本、模型输出、UI 自报 role/Context/administrator 不构成可信事实。宿主不能仅转签未经核对的外部声明。

Context 可空，含义仅为“本次没有 Context 范围”，不代表全局、不代表默认项目、不继承上一次入口。非空 Context 也不自动授权；入口不同不求权限并集。对象引用以领域身份与来源定位，显示名/路径不是独立身份；资源范围须说明单对象/集合及动作，不能以自然语言名称推导递归范围。

修改请求具有调用意图标识、期望修订和规范化目标；同一主体/入口/能力/意图标识重送相同内容返回原结果，不重复写；相同标识不同内容拒绝。去重保留期限、跨重启保证与意图查询需在实现契约证明，不能假设无限期。删除/解除与新建必须是不同意图。只读可重试但须重新判可见性。

结果至少区分：已确认提交（有权威修订/证据引用）、业务拒绝（未提交）、依赖不可用、确定失败（已证实未提交）、结果未知（无法确认是否提交）。超时/断连不是业务失败。保存返回不明确时先按意图查询或回读权威修订，未知期间不换新意图盲重试。取消在提交前可确认未提交；提交后返回已提交；无法确认则未知，取消不回滚事实。失败/未知不得伪造成功通知。

每次写入以期望修订检查本域对象/关系；旧修订返回冲突与获准可见的当前依据，不最后写入获胜、不自动合并。跨域变化不宣称全局事务；依赖读取提供来源修订，提交时需失效则拒绝/重验。历史证据记录当时依据，当前查询重新检查授权；撤权后历史记录仍保存但不得继续向无权者披露。

## B：分面与依赖最低行为

提供面为AIC-01…04，roles是本模块内职责分面，不创建第二个跨域owner。消费 permissions 的配置/职责读写判定、shared 的修订提交/意图查询、获准连接元数据（连接稳定引用、模型标识、当前就绪/不支持/未知及来源修订）。连接描述不得返回Key，也不承诺描述时就绪等于调用时授权/可用；AI不能自行探测执行模型。范围/主体事实由宿主核验后注入，AI不导入space、workflows私有状态，permissions也不回查AI表。消费者提供执行身份事实不能仅使用配置ID替代真实主体。

私有面为配置存储、提示组织、职责索引和有效性计算。app负责绑定窄端口与可信入口；通知只含可见性受控的配置/关系修订失效提示，消费者重查，不令通知自动替换在途依据。旧版本保留技术方案/期限尚未冻结；不足以保留解释证据时不能承诺AIC-04历史可追溯。

## A/B/C/D 与准备度门槛

A：配置/职责/选择/授权/运行分离、兼任不合权、在途来源不被新配置覆写。B：四项能力、不可变依据、停用与元数据可用性细化及样例。C：并发实例隔离、在途撤任撤权、同模型输入隔离、历史版本恢复。D：停用对新工作策略的产品细节、配置删除与版本/提示保留期限；完整记忆和内部循环不在本稿范围。

准备度：业务草稿可审阅；配置/职责查询可先用窄替身细化，正式实现接口前需消费者确认AIC-04历史依据和范围表示并批准B。未确认D不实施永久清除；C须在宣称并发/接续能力前以真实提供者验证。角色名称不得作为临时权限捷径。

### AIC-04：配置复用、执行身份与信息来源（F01/F03）

角色配置复用不复用上一次会话输入/许可/外部session；实际工作主体、入口、配置修订、职责与任务分配分别关联。主AI规划、秘书整理、执行产物、审查建议不能仅按角色名自动取得后续动作权；交接只交获准输入和证据引用，workflows保存责任轮次，permissions逐动作判权。

运行输入/衍生内容来源由conversations或workflows等实际owner保存，AI配置不维护另一全局来源账本。外部Agentsession由connections关联，不因两个Context选了同一角色而共享会话。无法确认外部session信息隔离时标能力限制；需要合并/重用另作获权动作。不承诺外部模型遗忘。未来角色经验/公共策略共享只有接口边界研究，无默认共享、无首版记忆开发。

断言：秘书在C1的可读资料不出现在C2输入；改任执行仍须独立外发/工具授权；前任配置停用后历史可解释但不准据旧依据新派发。一个角色兼任执行/审查不自动取得最终Acceptance权。

## G2/G6 与跨对话持续工作补充（2026-10-31）

本节明确 AI 配置在基础对话与长期工作的边界；完整映射见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

**G6：模块配置归属。** AI/roles 拥有角色描述、提示、模型/连接引用、职责关联及其修订；不保存 Provider Key、权限许可、Conversation 历史、Task 检查点或 Operation 状态。AI 配置可被多个 Context 选择，但每次实际工作必须绑定当时采用的配置/职责修订；配置更新不静默改变在途任务的身份与输入。

**G2：工具循环边界。** AI 配置提供模型/角色选择和行为描述，不拥有原生 API 的逻辑工具往返状态机。Conversation 组织本轮输入、工具意图、结果回注与定稿；connections/api 处理 Provider 协议；permissions 和 connections 负责授权与真实调用。外部 DSH/Hermes 的内部循环不由 WEX AI 配置接管。

**跨对话持续性。** 角色配置可在新对话中重新选用，但不代表角色记忆或模型隐藏上下文自动延续。长期工作进度、执行历史和下一步依据归 Workflows；需要共享的角色经验/公共策略库仍是长期研究，不在本补充中默认启用或创建第二份记忆账本。
