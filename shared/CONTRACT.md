## SH-01 路径解析、定位与技术读取

**目的/消费者**：app 定位根，各域从自己拥有的命名空间读资料，不各拼 AppData；消费者包括全部领域及诊断/备份入口。可信宿主注入已核验的路径与平台能力，不信任 Renderer/插件自报的绝对路径、Context 或资源身份。Context 可空（公共数据），非空仅为定位资料，不能充当授权。

**资源/权限/权威**：公共根、Space 工作区、独立 Context、外部引用可跨盘；安装目录不等于数据目录。提供方做技术范围/路径校验，业务可见性仍由 owner 与 permissions 检查；不让“读任意路径”成为公开通用出口。只读到现存数据及其版本/可用性证据，不改业务状态；定位索引是可重建投影，不能倒写本体。重解析点/别名/盘符变化须重新核实身份，不能字符串前缀即证明在范围内。

**结果/恢复/并发**：不存在、缺盘、权限拒绝、格式损坏、不兼容、超时/断连分别保留，超时不等于不存在。取消读仅停止等待时不得声称平台 I/O 已停。重复读可重试但绑定当前定位和版本，旧根迟到结果不能覆盖新根。移动/复制产生重复身份时回报 owner；不擅自搬迁、合并或新建空资料覆盖原引用。读取遇并发修订须返回版本依据或一致性限制，不拼出假快照。

**具体断言**：Context 在 F: 失联而公共根 D: 可用时，公共资料仍可读、F: 记录仍在，不写空 Context；用户把同 Context 放入第二 Space 后实际文件无复制；带重解析点的删除/读范围不能越界；旧定位检查迟到后不切回 F:。网络盘/可移动盘支持边界须单列实测。

## SH-02 受限技术提交、修订与持久结果

**目的/消费者**：各领域可靠保存自身决策与记录；connections 保存 intent/attempt/观察，workflows 保存工作轮次，permissions 保存授权，shared 不解释它们的状态含义。可信领域写入口已完成授权与业务不变量检查；Context 可空，例如普通调用/公共配置。资源是指定技术存储单元与 owner 命名空间，不能因共享库获得其他域任意写权。

**提交/证据**：给出可验证的提交依据与修订；明确区分已确认提交、确认未提交、提交结果未知。返回技术写失败不能自造 Task 失败、Operation 失败或授权恢复决定。期望修订不符须冲突，不静默 last-write-wins；重试使用原意图/去重依据并核查已提交结果，去重格式由后续契约决定。

**失败/timeout/断连/取消**：写前拒绝与写中磁盘满/锁竞争/连接丢失不同。提交确认丢失时可能已落盘，必须返回 unknown 或等价的“不足以断言”，不能当失败覆盖重写。取消请求可能与提交竞态；停止等待不证明回滚。unknown 后只先查提交标识/版本/完整性，无法确认交 owner 决定，不重新执行外部动作来“补保存”。仅在提供方已声明且可验证的意图作用域、请求一致性、去重保留窗口及并发重复规则内承诺重复请求不产生第二份相同记录；同一意图关联但内容不同须拒绝，不得套用旧结果。窗口过期、记录不完整或关联无法判定时报告不可判定并交 owner 核对，不新建重复记录或宣称安全重试。迟到旧修订不能覆盖新状态；具体幂等保存期、冲突策略须在实现契约声明并验证。

**原子边界**：同一受支持技术事务可由 owner 要求状态与记录同时提交；原子范围必须明确，不能默认跨目录、多个库、附件、系统凭证、Agent/远端文件原子。外部请求不得放长数据库事务；outbox 也不保证外部 exactly-once。外部生效而回执未保存时，技术层保留观察/未知，不做业务重派。

**具体断言**：模拟 commit 已成功但 ACK 丢失，调用方不得生成第二 attempt 或覆写旧记录；查回相同提交后返回其依据。两个写者持修订 7，第一写成 8，第二明确冲突且资料不回到 7。intent 确认未提交时外部调用次数为零；外部已写文件、回执保存 unknown 时，不再次写文件。busy 超时须无虚假成功，恢复后是否提交必须核实。

## SH-03 一致备份、恢复与迁移基础

**目的/消费者**：app/用户维护入口及各数据 owner 能保留资料并验证可恢复性。前提为明确范围、版本、写入屏障或存储支持的一致备份方式；可信宿主发起，Context 可空或选定多个 Context，单 Context 授权不自动扩大到全根。敏感读取/写目标与维护权限分别检查；秘密默认不进入普通备份。

**权威/证据**：提供技术快照、清单、校验和不包含项；清单记录所含根、格式/修订/时点、缺失附件和外部引用，不承诺同一时点跨所有存储。运行中 SQLite 不只拷主 db；采用驱动支持备份或停写正常关闭后复制的方式须实验。WAL 可能含已提交数据，禁止删 WAL 当修复；备份不等于外部资源/凭证备份，恢复本地历史不回滚外部事实。

**失败/取消/恢复/并发**：临时目标完成校验再发布（B），中断/超时不标成功；保留原件与未完成诊断。恢复先格式/版本/完整性校验，在副本迁移并保留迁移前资料（B）；版本不兼容拒写/只读，不空库替代。单库事务回滚不代表跨文件迁移回滚；重试先识别已完成阶段，不重复覆盖。迁移/恢复与正常写入须协调屏障，第二迁移拒绝或等待；算法待定。取消中途不可声称已原子恢复旧环境。

**具体断言**：WAL 活跃写入期间备份能恢复最后声明的快照，不能以只有主库的复制品通过；附件缺盘清单标缺失，不报告全量成功。迁移强杀后原库可读、半成品不成为正式根；旧版本程序拒写新格式。恢复较旧备份后未决 Operation 交领域核对外部事实，不自动重放。秘密扫描发现 Key 则备份验收失败；外部引用目录未被复制/删除须与清单一致。

## SH-04 秘密配置与受限使用衔接

**目的/消费者**：AI 配置仅保存连接/模型引用，凭证引用由 connections 的连接配置持有；可信连接宿主把秘密用于明确获准目标；消费者不能得到通用“列出/导出所有秘密”能力。Context 可空（配置凭证或普通 API 调用），有 Context 也不意味着可用 Key。可信 app 注入平台保管机制；用户明确配置与运行时使用为不同入口。

**资源/权限/权威**：秘密保管与引用有效性归 credentials，动作/目标/资源授权归 permissions，目标适配器与最小秘密提供边界归 connections 宿主。Key、登录成功、共享 Provider 不授予 Context/文件权限。平台加密不证明宿主调用方可信；Windows DPAPI 用户边界不能承诺防同用户其他程序。外部 DSH 可有自己的凭证与环境，WEX 未配 Key 不能证明它无权限；环境变量、句柄、文件继承须另验。

**写入/证据**：连接配置仅持有受控凭证引用，AI 配置不复制该引用或秘密；日志/错误/任务卡/视图/模型提示、诊断与普通备份无秘密正文。审计记录引用存在/版本/使用关系与必要结果，不回显令牌、完整认证头或可重放材料。持久回执不能作为永久 bearer 授权。秘密提供只给绑定目标和本次有效主体；具体进程传递协议列 C 技术待验证，不能先写任意插件均可 resolve。

**失败/撤销/恢复**：缺失、不可解密、平台拒绝、授权拒绝、目标停用分别报告；保管/替换超时可能提交未知，查引用版本后再试，不盲覆盖；调用超时/断连由 connections 判断副作用 unknown，credentials 不重试远端。取消配置不证明已回滚，取消使用不证明秘密已从远端收回。替换/删除/撤销与在途交付竞态须核对版本和当前授权，旧版本迟到不复活；已经交给外部的资料不能承诺撤回。

**具体断言**：模型提示要求“打印 API Key”时仅得到拒绝，日志无原值；连接成功但目录未授权时文件读仍拒绝。替换 Key 时旧修订配置保存失败不得重绑旧引用；撤权后未派发请求不再取得秘密，在途已传出仅留事实与限制。外部 DSH 自带 Key 的测试须注明其独立权限，不能作为 WEX 权限隔离通过证据。

## SH-05 使用关系恢复与重装隔离

**目的/消费者**：app、credentials 与 permissions 区分普通资料复用和敏感使用恢复。前提是可信宿主提供经过识别的生命周期事实；Context 可空，根路径/配置里的安装标识/旧批准不能自证可信。识别机制尚待设计，不能仅以是否可解密决定是否可用。

**权威/权限/证据**：shared 技术层执行使用关系限制并报告，permissions 决定有效授权；历史授权记录保留审计而不恢复有效许可。重装 Windows 或卸载重装后，即使凭证库仍在且可解密，用户须重新配置凭证、重新授权；旧全局开关、目录/工具许可、待审批/已批准操作不可自动生效。普通资料、环境、插件可识别复用，不能自动启用插件/执行脚本/重放工具。正常重启与普通升级不是自动重装；普通目录迁移也不一律重配。

**失败/恢复/并发**：生命周期无法确认则敏感恢复受阻并解释，不能把普通项目一并清空。判断超时/平台断连保持受阻，重试复核当前使用关系与修订；取消重新配置不恢复旧许可。旧宿主回调、旧引用缓存与新安装并存时不能让迟到结果绕过新关系屏障；失效/清理实现待验证，不能把删一个配置文件当完整证明。

**具体断言**：卸载重装保留根且旧 Key 可解密，读取旧会话成功，任何旧引用使用均被阻断，旧审批不派发；用户重新输入凭证并重新授权后，先核对未决外部事实再接续。正常重启同数据根对照无需重填全部 Key；系统重装/新 SID/盘符变化分别测试，不广泛放宽 ACL。普通升级迁移成功且关系延续按兼容策略保留，不冒充重装重置或绕过重装限制。

## 最小依赖、私有机制与通知

| 提供方 | shared 所需最小行为 | shared 不得代办 |
|---|---|---|
| app/平台适配 | 已校验根、运行/使用关系、文件与秘密平台故障证据 | 以 app 容器替代窄能力；自行决定后台/卸载业务 |
| 数据 owner | 受限写入意图、期望修订、业务授权与恢复决定 | 解释 Task/Operation/Conversation 状态 |
| permissions / 连接宿主 | 当前可信主体/动作/目标的决定与最小交付边界 | 因 Key 存在批准调用；重装恢复旧批准 |

上述 app/平台与 permissions 的事实均由可信宿主以窄依赖注入；shared 不反向 import app 或 permissions 实现，不读取它们的私有库，不通过公共出口索取整个容器。表中是运行时事实来源，不是源码依赖方向，以免 shared 基础机制与 app/权限域形成实现环。

私有：驱动连接、锁/事务实现、路径规范化、序列化/校验、凭证后端、句柄释放、备份临时文件与迁移执行；不把各领域类型集中搬入 shared。诊断/可用性/引用失效通知只提示重新读取事实；重复/丢失通知不能增加授权、重放提交或决定业务恢复。通知名称与取消语义不冻结。

## 替身双方契约、集成与完成标准

施工范围：后续按真实共用需求实现路径/技术提交、备份恢复基础与凭证平台适配；不提前建设万能类型包，不写调度/Task 状态机、权限政策、跨资源分布式事务或外部操作重试器。当前批次仅文档，没有产品代码、数据迁移、远端写入或 Actions。

消费者替身须能区分确认未提交、确认提交、commit ACK 丢失、旧修订冲突、缺盘、不可解密、可解密但重装受阻；消费者证明不会在 unknown 后重写/重派，不把存储失败改成外部失败。真实 storage/credentials 提供方须跑同一行为样例，另外证明 WAL/文件锁/平台错误/脱敏与范围约束；替身永远立即成功不能作为契约证明。

目前无产品入口与正式测试命令。实施时由 shared owner 就近补实际测试入口，app 装配者补真实组合路径：先 storage 与一个真实领域提交/恢复，再 credentials + permissions + connections 的受限交付，最后 Windows 重装接回/备份演练。每次结果记命令、平台、驱动/版本、样例 ID、证据位置及未覆盖项；不得虚构测试通过或触发 Actions。

完成标准：SH-01..05 的具体断言由消费者和真实提供方共同通过；故障注入有实际结果，提交未知不变失败重写，无跨外部原子承诺，无日志/备份泄密，无第二份业务/权限权威；正常重启、普通升级、卸载重装、Windows 重装分别留证。准备度：**语义草案可审查，未冻结实现契约，未实现/未运行验收**。缺口：驱动/事务范围、提交身份与去重策略、跨目录屏障/恢复清单、Windows 凭证与使用关系识别、在途撤权竞态、取消边界、完整备份恢复演练。

### SH-01–03：配置、日志、容量及诊断技术边界（F05/F08/F09）

建议提供带owner/格式与修订的受限配置技术读写/默认值装载/迁移结果；业务字段校验、生效时机与在途版本由各owner决定，shared不拥有全局“最新配置”业务总表。坏配置可诊断并保留原件，不以恢复默认覆盖秘密/授权/工作事实。

日志管道只处理结构化来源封装、限量、轮转、路径与脱敏；插件stdout/stderr始终标记不可信来源，不能把伪造JSON提升为permissions/Operation事实。日志目录掉线或磁盘满时报告技术故障，已提交业务结果不改失败；强审计必须持久才能执行哪些动作仍为permissions/调用方的D政策。审计与Operation/Verification不随普通日志轮转删除。配置、日志、诊断均可先在现有模块实现，不预建新目录。

容量观察区分业务数据、派生索引/缓存、日志、临时工作与外部产物；清理建议交owner核对引用和在途使用，不递归清理外部工作目录。诊断导出由各owner提供当前获准/脱敏片段与完整性说明，shared只收集/写包，不全库扫描绕授权。数据根不可用时是否允许最小系统诊断位置是B/D，实际位置为C，不能暗写C盘大量资料。

索引只为派生加速，记录来源/版本和缺失范围；撤权/掉盘后查询必须由owner重判，不能让索引返回私有摘要/数量。根写锁/多进程句柄与命名空间隔离提供技术证据，不替代runtime资源占用或permissions。sqlite并发/WAL/真实崩溃恢复及多用户Windows锁为C，不把单进程读写推导成安全多写。

断言：日志写失败但Operation已存，查询仍显示原事实并有诊断故障；轮转后核验引用可定位；无权诊断片段不进入导出包；清缓存不删Task证据；只读副本迁移成功不能证明新旧进程并发写安全。

## 第七批实际实现（2026-10-31）

本节为当前产品实现范围，先前“没有产品代码”描述是历史状态。公开入口 `shared/src/index.ts`，真实消费者为 `permissions/src/service.ts` 和 `app/src/foundations.ts`；无反向业务依赖。

- `Store.read/commit/query`：一个命名空间聚合快照及原意图记录；期望修订 CAS；明确 committed / not_committed / unknown。成功及意图记录在同一 SQLite 事务；命名空间在构造时由可信宿主绑定，消费者不取得 DB 句柄。读取故障抛错，不能冒充空库。
- 意图作用域为同一数据库、命名空间及 intent；原提交包含 expectedRevision 与规范 JSON 内容，完全一致重送返回原修订，不同内容冲突。原意图记录当前不自动过期、不提供清理；跨重启保留。unknown 后通过原 intent query/权威记录回读，未确认不重建外部动作。
- `openSqliteStore/createSqliteStore` 为可替换 Node SQLite 适配；`SqlitePort` 是技术驱动接口；对外不承诺跨库/文件/服务原子性。不将本批适配器冻结为全产品存储选型。当前使用 Node 24.22.1 内建 SQLite，未验证 Electron 的 Node 版本适配。
- `inspectRoot` 只读现存 `.wex-root.json`（format=1、id非空）；不自动初始化、移动、修复旧根。诊断 missing_path / missing_volume（需平台 ENODEV/ENXIO 证据）/ permission_denied / corrupt / incompatible / identity_conflict / unavailable；ENOENT 不推断缺盘。
- `resolveWithin` 重新核根身份并用 realpath + relative 检查现存路径；拒绝绝对路径与链接逃逸。结果只是当时定位观察，不是抗同用户恶意换链的文件操作凭证；未来真正读写/删除出口仍需句柄级平台校验。
- `RootLock` 可替换。默认 `directoryLock` 是保守合作目录锁：原子 mkdir、随机 owner、释放核对、不自动清旧锁。进程崩溃会留下锁并阻断，尚无安全自动回收；不是 Windows OS 活性锁/ACL/沙箱证明。
- `createDiagnostics` 只允许技术 code/module/level 白名单，不接受自由消息正文、任意字段或业务证据；sink失败明确返回 failed。普通诊断不是 Operation、权限审计或 Task/Artifact/Verification 账本。没有日志文件轮转/保留策略实现。

测试：`npm run test:shared`。真实 SQLite 与测试专用内存替身共用 `shared/tests/store-contract.mjs` 向量；ACK丢失通过真实 COMMIT 后的传输端口异常注入，另有真实只读与跨进程锁竞争。不以替身证明持久性。SH03–05 的完整备份/Windows凭证/ACL/重装关系恢复均未实现，C/D保留。

## 第七批收尾修复（2026-10-31）

inspectRoot 在读取根身份标记前通过 lstat 检查，拒绝符号链接和非普通文件；缺失、损坏和不兼容仍按既有结果分类。该检查不是句柄级原子操作，不承诺抵抗同用户恶意并发换链。

createDirectoryLock 提供可注入文件系统端口用于故障测试，默认 directoryLock 行为不变。创建锁目录后若owner写入失败，只在owner内容与本次随机token完全一致时删除该文件，并仅尝试删除空目录；若内容未知、清理失败或目录非空，保留锁并返回unavailable，避免误删其他执行者的占用。

## G1/G6 技术基础与跨对话持久性补充（2026-10-31）

本节对应基础能力 G1/G6；完整 owner 与实现状态见[基础能力落地映射](../docs/planning/FOUNDATION-CAPABILITY-IMPLEMENTATION-MAP-2026-10-31.md)。

**G1：持久资料的技术存储边界。** Shared 提供受限技术存储、路径定位、提交修订和未来备份/恢复原语；不拥有资源正文的业务含义、Space 引用关系、Conversation 附件语义、Task/Artifact/Verification 或统一资源索引。外部文件仍在原位置；WEX 管理的持久副本必须明确写入用户选择的数据根并由单一资源 owner 管理，不能将附件字节塞进 shared 的通用聚合快照。

**G6：配置、凭证、日志三者分离。**
- 配置：各模块拥有字段含义、默认值、校验、启停和迁移策略；Shared 只提供经证明必要的技术保存原语，不建立全局配置中心。
- 凭证：`shared/credentials` 负责平台秘密保管与受控引用；实际使用目标和授权由 connections/permissions 决定，持有或可解密 Key 不代表获权。
- 日志/诊断：当前 `shared/src/diagnostics.ts` 是受限字段的诊断 sink，不是持久化运行日志、日志查询/轮转/导出平台。后续可评估技术日志写入能力，但不得混同 Connections Operation、Permissions 授权审计或 Workflows 任务/验收证据。

**跨对话持续性。** Shared 只保证其实际存储原语所声明的提交/回读语义；不解释 Task 检查点、不决定恢复、不承诺跨多个数据库/文件/外部服务原子提交。持久工作状态由各业务 owner 写入自己的命名空间；应用重启后按 owner 查询，不通过复制全局快照建立第二份业务权威。

本补充不表示 Windows DPAPI、系统凭证、完整备份恢复、日志持久化/轮转或安装重装关系已经实现；按现有 C/D 门槛逐项验证。
