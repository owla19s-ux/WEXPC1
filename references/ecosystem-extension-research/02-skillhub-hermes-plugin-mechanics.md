# 扩展生态机制补充：SkillHub 与 Hermes 插件模型

状态：公开资料静态研究；仅新增参考文件，不修改既有研究、架构文档或需求案例。日期：2026-10-28。

## 1. SkillHub × DSH：技能与插件是两种不同交付物

来源：
- https://github.com/Tencent/skillhub
- https://github.com/Tencent/skillhub/blob/main/dsh-plugin/README.md

SkillHub 仓库包含 Open API 文档、DSH 插件和官方 Skills。DSH 插件负责目录搜索、技能详情、版本选择、安装/卸载、插件市场 UI 与本机插件安装；Skill 则通常是 Agent 可发现的文件目录，至少包含 `SKILL.md`，可附带脚本和参考资料。

值得 WEX 借鉴的分层：
1. **目录服务**：搜索、分类、榜单、详情、版本、评测、签名。
2. **客户端集成插件**：将目录能力呈现到宿主 UI/Agent 工具中。
3. **技能包**：供 Agent 按需读取的说明/脚本/资料。
4. **宿主扩展插件**：实际进入宿主运行环境、注册工具或 UI 的代码包。
5. **本机生命周期管理**：安装来源、版本、更新、卸载、已安装状态和重启提示。

这些层不能混为一谈。安装 Skill 文件和安装可执行宿主插件的风险、权限与生命周期完全不同。

## 2. 安装流程中的信任边界

SkillHub 插件 README 描述的插件安装计划会核验来源与 pinned commit，并在本机调用 DSH CLI 安装插件；技能 ZIP 下载会拒绝路径穿越并检查 `SKILL.md`。这提供了来源固定、安装计划和路径校验的参考，但不是对插件运行行为的安全证明。

特别注意：
- 宿主插件安装会把第三方代码装入当前 profile，可能在宿主权限下执行。
- 技能说明文件本身通常不等于可执行程序，但 Agent 可能遵循其中指令或执行其附带脚本。
- 安装验证、签名/来源验证、权限审批、运行隔离是不同控制。
- “已安装”不等于“已激活”“健康”“已授权”或“可安全执行”。
- 自定义目录 API 也必须视为信任配置，不能只因是 JSON/HTTP 接口就默认可信。

WEX 的候选架构应分别定义 ArtifactKind、来源/版本、声明能力、权限需求、激活状态和执行边界；具体类型命名待设计，不在本文件冻结。

## 3. Hermes：插件类型有不同的选择与生命周期语义

来源：
- https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/plugins.md
- https://github.com/NousResearch/hermes-official-plugins

Hermes 文档描述的类型包括：
- **General plugins**：工具、hooks、slash commands、CLI 命令；可组合启用。
- **Memory providers**：替换/增强记忆后端，通常同一时刻只激活一个。
- **Context engines**：上下文压缩引擎，通常单选。
- **Model providers**：注册多个模型后端，再由配置选择使用。
- **Delegation providers**：委派策略提供者。
- **Middleware / Desktop extensions / Gateway platforms**：另有独立扩展面与注册机制。

这提示 WEX 不能只设计一个无差别的“插件开关”。扩展点至少需要表达：
- 多实例可组合，还是互斥单选；
- 贡献能力，还是替换某项宿主策略；
- 是否参与每轮执行，还是只在配置/界面层运行；
- 何时加载、何时可见、何时允许调用；
- 停用时是否需要排空在途操作、保存状态或重启。

这些是对现有生态的归纳，不代表 WEX 已采纳同样的插件类型。

## 4. 目录固定版本与更新可复现性

Hermes 官方插件目录采用经审核的 commit pin；安装固定到目录审阅过的提交，更新时再移动到新的审阅版本。SkillHub 也在安装流程中使用版本和安装计划信息。

WEX 能借鉴的原则：
- 记录发布来源与精确版本/提交；
- 将“发现更新”与“执行升级”分开；
- 升级前检查兼容性、权限变化与依赖变化；
- 失败时保留旧版本或给出明确恢复路径；
- 本地开发安装、市场安装、组织私有分发应可区分。

仅固定版本不能保证代码安全；它主要改善可复现、审计与回滚能力。

## 5. TodayAI 的开发者入口：可接入内容源，不等于能接管其个人 Agent

来源：https://todayai.com.cn/connect

公开页面提供 TodayAI Skill、RSS 与 REST API 示例，面向内容获取和开发者集成。它可以作为外部服务/内容源接入的研究样本，但公开页面本身不足以证明其个人记忆、完整 Agent 生命周期或内部插件系统可被第三方替换。

WEX 需区分：
- 接入 TodayAI 的公开内容 API；
- 安装其 Skill 供 Agent 使用；
- 接入其个人 Agent 运行时；
- 复用其记忆/任务服务。

前两项有公开接入线索；后两项不能据现有公开资料假定成立。

## 6. 对 WEX 的设计问题（留待需求对冲）
1. Skill、宿主插件、连接器配置、模型 Provider、Memory Provider 是否需要不同的包类型与权限模型？
2. 能力市场是否只是分发目录，还是还承担评测、来源验证、签名、组织私有库和更新策略？
3. 插件在运行时新增后，如何原子发布能力目录和 UI 视图？旧调用如何结束？
4. 互斥 Provider 与可组合插件如何表达？配置切换是否需要重启？
5. 第三方插件的构建脚本、运行权限、网络和文件访问如何受控？
6. 如何保存来源、精确版本、评测结果、授权决定和卸载/回滚历史？

## 结论
复用生态能力确实可能显著减少 WEX 自己实现业务功能的工作量，但不能替代 WEX 的宿主核心：身份与上下文模型、能力契约、权限裁决、调度/回执、生命周期和持久化边界。优先复用具体能力，自己掌握组合与治理。
