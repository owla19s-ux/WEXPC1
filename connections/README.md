# connections — WEX 内部与公共连接/适配体系

**状态（2026-10-30）**：代码目录职责已确定；已有 headless 与受控交换独立实验，仍以连接器研究与模块划分为主，尚未形成 WEX 产品级公共连接协议或完整调用闭环。旧文档中“WEX 连接器默认采用 Cordis”的意见已废止。

## 职责

- **内部连接职责**：在需要跨功能域/对外交换时，将 WEX 内部的受控能力接入连接体系；正常模块内部调用不必强制绕行公共边界。
- **公共连接/适配职责**：作为内部能力与外部能力的双向交换边界，负责能力描述、访问身份、请求分派、授权检查接点、结果/错误/回执映射。用户比喻的“插座墙”就是现有连接系统，**不是另一个新增子系统**。
- **具体连接器**：处理目标服务协议、连接状态、参数和产物转换；不持有 Space/Context、任务状态、权限账本的权威副本，不需要依赖 WEX 内部私有服务源码。
- **优先级**：外部 Agent 客户端连接器优先研究（复杂任务交接、会话入口、产物、结果未知）；API、本地文件/Git、GitHub 等内置能力用于基础调用、独立核验及恢复。不以工具连接器数量为目标。
- **安全**：发现/注册能力不意味着授权。插件或外部进程仅获经校验的最小能力；接口封装本身不替代进程隔离。

## 已有子模块

## 最小边界实验（2026-10-30）

`experiment/boundary.mjs` 仅提取 headless 实验需要的装配：连接器描述 `dsh.headless.run`（有副作用、不自动重试、结果可能未知），接受任务引用、通过受控 `readTask` 回调取得本次任务文本，再返回结果或结构化错误。宿主授权外部调用与任务读取，先存 attempt 再派发，最后存 result；连接器拿不到宿主对象、Context 或权限账本。此接口不是系统沙箱或正式公共协议。

实际执行 `node --test connections/experiment/boundary.test.mjs`：5 项通过，覆盖双向交换、两类拒绝、派发前回执写失败、派发后异常与结果写失败（保留 observed 证据）。服务与连接器执行使用测试替身，未声称连接外部服务或实现磁盘回执系统。失败写回不能自动重试副作用请求。B 的真实进程协议与失败证据已足以限定此小原型，但真实模型成功链路仍未验收。

## 第二批：受控边界与执行责任

| 职责 | 维护内容 | 明确不拥有 |
|---|---|---|
| 内部连接/宿主装配 | 把领域公开操作包装为所需的最小能力；绑定可信调用来源 | 领域内部实现、可变全局对象或通用数据库写入口 |
| 公共调用边界 | 能力/连接可用性、权限检查接点、单次操作尝试与回执、错误/断连/未知观察 | Task 完成、工作流路线、角色职责、权限政策 |
| 具体内置连接器 | 连接配置、协议适配、真实资源操作及服务专属诊断 | 自批权限、写业务任务表、插件宿主通用生命周期 |
| 外部 Agent 连接器 | 外部进程/会话关联、任务交接和所能观察的结果证据 | 外部 Agent 循环、任意 GUI 会话控制、未经证实的取消保证 |

调用方向：对话/工作流/获准 UI 业务入口请求能力 → 宿主受控边界检查并记录 → 对应连接器执行。反向方向：外部请求 → 同一类受控边界建立主体与范围 → 最小领域能力 → 领域返回获准数据/结果。外部提供的 Context/任务名称不是可信身份；连接器不能自行选择更高权的宿主身份。

双向通信不等于源码互相依赖：`app` 装配调用者与公开提供者，连接器仅消费注入的窄服务，不导入 `space`、`workflows` 或 `permissions` 私有实现。一般领域内部操作不强制经过公共连接层；对外出口和回调必须经过适用的受控边界。连接边界调用 `permissions`，最终领域/资源入口继续保护不变量与实际可用权限。

**操作事实的唯一维护方**是本目录的宿主调用责任：派发前保存尝试依据，派发后保存观察和结果。连接器只报告，不自行维护账本。`workflows` 保存任务/流程轮次及这些操作的引用，不另写同一操作的正式状态；普通聊天或单次读取也可有操作回执，无须先创建任务。WEX 受控的非 Task 副作用请求同样要检查已有冲突/未知占用，不能绕过 runtime 对受影响资源的暂停；资源协调责任按需由宿主注入，不要求创建 Task/流程实例，也不让连接器私有导入 runtime。回执存储机制复用 `shared/storage`，不能把“数据库写入成功”解释为外部动作成功。

受控回调仍是一项独立的能力使用，要按目标及动作判断、记录必要结果；实验中的 `readTask` 只证明窄数据交换，不代表已有通用回调账本、身份认证或跨进程撤权。外部调用成功、结果成功保存和业务验收通过分别判断。

内置连接器由可信应用装配即可；未来 WEX 动态插件 `plugins/`、独立 DSH 插件宿主 `dsh/`、外部 DSH Agent `connections/dsh/` 互不作为强制运行前置。当前不建设注册框架或最终 IPC。

## 公共网络适配边界补充（2026-10-31；条件候选）

因[应用基础能力审查](../docs/research/APP-FOUNDATIONS-GAP-AUDIT-2026-10-31.md)发现代理、网络切换、离线和连接诊断没有统一的可验收行为，记录`connections/network/`为**条件性候选目录**：只有多个真实连接器出现可复用的网络/代理技术接线与测试需求时才创建，不把它提前当成新的网络子系统。各连接器仍负责自己的协议、超时、错误/重试和能力就绪；通用偏好归应用配置接线，Key归shared/credentials，授权归permissions。

用户切换系统代理/特定Provider代理、证书错误、远端离线和宿主进程网络失联须分别报告；发现可达不等于获准调用，网络超时不等于外部动作未发生。内部领域函数调用不因存在连接墙而必须统一经过网络层。网络诊断和远端请求不得默认暴露凭证、用户Context资料或越过实际资源权限。
