## 第二批：调度与恢复责任

1. 根据明确版本的定义/任务和适用职责选择执行方案，协调 WEX 管理的并发配额、工作区与冲突资源；排队不等于已授权或已执行。
2. 派发前复核任务/资源条件，经 `connections` 宿主调用边界授权并记操作尝试；本域保存工作轮次与操作引用。实际调用和取消由连接器/外部运行时执行，本域不直接操作文件/进程。
3. 根据已保存回执与独立核验推进、返工、阻塞或升级；晚到结果关联原轮次，不静默覆盖重派后的当前状态。退出/超时不等于副作用未发生。
4. 断连或重启先恢复本地关联，再查询可获得的外部会话/进程/资源状态；已发生文件修改但结果未知时，先阻止可能冲突的再次派发，重新核验版本和产物，不能盲重试。核验无足够证据则维持未知，交有权主体裁决。
5. 占用协调以实际冲突资源为依据，而非按 Context 或 Agent 名称隔离；目录别名、Git 共享元数据、构建输出和同一外部会话都可能冲突。资源解析由连接器提供，WEX 内协调占用；普通对话或单次连接引起的受控副作用也遵守同一冲突检查，无须先建 Task。此资源协调责任可由宿主按需装配，不以前置完整调度器为条件。外部自行启动的工作不受本地占用表保证。

关闭视图、解除 Space 引用不取消工作。程序退出由 `app` 与本域协调保存未决状态及停止请求；没有常驻宿主就不承诺关机后继续。撤权由权限域作决定、连接/资源边界阻止后续动作，已派发动作的真实停止由执行方确认。

待实验：并发队列/占用持久化、实际资源身份与工作区隔离、崩溃前后派发间隙、重派/迟到回执、撤权和取消竞争、DSH 会话恢复。未选择锁粒度、租约算法、事件总线、后台进程模型或跨存储事务方案；不声称恰好一次执行。
