# workflows/modes

可保存和复用的工作流模式。各模式复用公共调度与连接，专属数据及视图就近维护。

状态：2026-10-30 按用户确认建立的源码维护目录，当前只有职责说明，尚无产品实现。目录不是运行时数据路径，也不代表独立插件、进程或编译包。

[源码目录与 Windows 数据要求](../../docs/WEXPC-SOURCE-LAYOUT-AND-WINDOWS-DATA-2026-10-30.md)

修改原则：实现与必要测试按实际需要就近添加；不预建技术分层。模块专属 UI 随模块，内置页面集中在顶层 UI。实现后补充具体入口和验证方式。

## 可选专业组合的责任

模式描述对象如何组合、专业规则与默认视图，不是 Context 的本体，也不要求存在执行工作流。本目录名称沿用已有布局，非执行的专业预设不因此转成调度业务，不新增模板顶层目录。

模式自有配置/专业对象与专业关系由该模式的领域规则维护；引用现成任务、角色、连接、资源时，其真相仍归原领域。专业视图只显示/编辑这些规则，不保存第二套 Task 或权限。模板生成草案不自动授予权限、调用网络或执行工具；实例化、配置覆盖及更新语义待业务契约细化。

同名节点以所属专业机制与明确身份解释，不能按显示文字分派执行；当前 React Flow 的 kind/组件名不成为正式专业类型协议。软件开发的需求/架构关系可无执行含义，不应强行写入工作流执行依赖。
