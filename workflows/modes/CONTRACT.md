## owner、非职责与依据

模式是可选专业组合：拥有模式配置、专业对象/关系及规则、默认组合建议；软件开发只是其中一种。模式可不含可执行工作流，Context 不是软件项目。模式不拥有第二套 Task、运行/操作账本、权限或角色身份；不把“需求对应架构”变成执行依赖。通用 workflows、space、permissions 不依赖具体模式；模式消费它们的公开能力。views 消费注入的专业规则/投影，modes 不导入 views 实现。

依据：根 README、modes 及 software-development README、研究决策 §6–8、全局地图、功能全景“软件开发模式”、views README 和视图审计。当前仅职责说明；四种原型节点及 kind 字符串不是正式专业类型身份。下表 B 推荐行为，受 A 边界约束。

## 公开能力

主体由可信宿主识别；入口可为模式面板、UI 选择器或获权内部调用。Context 可空；只有目标领域确实要求资源时才要求显式补齐，不强制新建 Context/Task。引用资源/角色/连接不扩权。无权对象与不存在对象向无权消费者等价不可用，禁止泄漏名称、关系端点或代码路径。

模式及通用对象变更均区分**确定未提交、确认提交、提交未知**，这是证据语义而非正式枚举。确定未提交才可称未保存；ACK 或原业务关联回读确认提交。ACK 丢失/保存超时显示待核对，逐 owner 按原关联查证，不重写或补偿删改；不可用时暂未查到不是未提交证明。取消只停止尚未开始步骤；已开始提交与取消竞态可能成功、确定未提交或提交未知，取消不回滚任何已提交结果。

|---|---|---|

## 最小依赖与装配

模式需要 workflows 的草案/Task 创建、受控修改、按关联查询与获准运行/核验投影；space 的获准资源与组织引用；AI 的角色配置引用；connections 的能力/就绪摘要（不拿密钥或直接执行）；permissions 的当前动作判定；shared 的持久化结果。通用域不得识别 software-development 目录、预设名或组件类型来执行业务。app 注入模式的环境中立规则给 views 和 UI 桥；renderer 不导入 Node 领域、凭证或模式私有存储。

私有实现：专业规则、实例默认/覆盖合成、升级计划和专业面板。通知只声明配置/专业修订变化；接收方获权回读，重复/缺失不构成业务写入。监听取消不终止任务。施工在 workflows/modes 下按实际专业需要就近实现；software-development 可维护自身对象/规则/面板；不预建所有职业模式或新的顶层 templates。

## 双方替身、集成与完成证据

模式消费者测试用提供方替身覆盖两种同名不同语义、缺规则、版本不兼容、无 Context、部分创建和撤权；断言不误执行、不泄漏关系端点。模式提供方以同一业务样例验证真实规则。通用 workflows 替身必须能返回“创建已提交但响应丢失”，其提供方契约必须支持按原关联查证；不得用成功直返掩盖分布式部分结果。权限替身与提供方验证模板关联不授予读取/发送/运行许可。

最小组合：软件模式需求—架构—文件引用+真实通用 Task；实例化中断后恢复；两个窗口编辑关系；升级与已运行 Task 并发；模式移除后回读历史；视图更换后对象不迁移。断言通用域无具体模式反向依赖，renderer 无 Node/凭证深导入。完成证据列基线、环境、实际命令、实例/通用对象关联与版本及未运行项。本批仅静态阅读，不声称组合测试通过。
