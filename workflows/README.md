# workflows — 工作流、任务状态与调度职责

**状态（2026-10-30）**：本目录是未来 WEX 工作流业务实现的职责位置；当前已有独立 React Flow 编辑**实验原型**，没有正式多项目并发调度产品代码。

## 职责

- 本域拥有工作流定义、任务交接/轮次、运行状态、产物引用、验证与验收记录；通过引用使用 `connections` 宿主维护的操作尝试及回执，不双写同一操作真相。外部 Agent 的自报状态不能替代 WEX 权威记录。
- 执行工作流与**非执行**的需求树、架构树、进度图是不同概念；广义视图体系的研究归 [views/](../views/README.md)，不把所有专业视图强塞进调度器。
- 简单连线不代表执行可靠：未来须研究断连/重试/结果未知、并发配额、文件资源冲突、重启恢复与跨 Context 的任务一致性。关闭编辑器窗口不应自动等于取消任务。
- 调度/运行语义与 UI 节点显示分开，使用哪个 Agent/连接器由 WEX 控制，具体通信在 [connections/](../connections/README.md)。
- 工作流定义与运行状态、视图布局不能合并成 React Flow JSON。

## 第二批：工作、执行、验收分别维护

| 内容 | 本域维护责任 | 不能据此推断 |
|---|---|---|
| 工作流定义/修订 | 可复用的步骤、明确执行依赖和运行规则 | 编辑或画一条线不会自动启动任务 |
| Task/工作轮次 | 单项目标、范围、分配、任务状态、返工/阻塞依据 | 工作流节点不是任务实例；重派不抹去旧尝试 |
| 流程运行/步骤进展 | 使用哪版定义、哪些任务等待/运行/交接 | 不覆盖连接边界的操作结果 |
| 产物、Review、Verification、Acceptance 记录 | 关联具体来源/版本/环境、收集结论、按验收规则更新任务 | 外部 completed、命令退出 0、审查通过分别不等于最终验收 |

实际文件/提交/远端产物仍以来源系统为事实依据，本域拥有的是产物引用与核验/验收记录，不是远端文件的唯一真相。证据必须对应被验收版本；后续变更不能继续沿用旧版本的通过结论。

调度决定执行时机、候选执行者、依赖条件与资源协调；连接器/外部 Agent 实施动作，权限域作授权判断。主 AI 提供规划与技术判断，程序流转按已适用的规则处理，不能替用户改目标或让模型自批完成。由 [runtime](runtime/README.md) 承接调度/恢复责任，不新增调度器顶层系统。

`AI/roles` 提供职责配置，`space` 提供关联范围；本域只保存本次任务分配与输入依据，不反向修改角色模板或 Context 本体。普通对话和单次连接调用不强制创建任务。

状态维度分开：连接是否在线、外部报告何结果、回执是否保存、任务是否需修复/阻塞/最终失败、产物是否通过验证/验收不是同一个状态枚举。本批只定归属，不冻结状态机。

## 第三批：模块契约设计入口（研究建议）

覆盖样本 L06/L07/L09/L10。围绕 Task/工作轮次、分配、证据接收/验收和恢复决策归并契约，连接执行与操作观察只作为依赖。可以在执行/判权/存储替身上验证真实任务行为，再与真实提供方组合；不能把 L06 整条链路分散实现成各域共管任务状态。

契约就近、公开出口/依赖约束、分层测试和模块施工方法见[统一研究](../docs/WEXPC-GLOBAL-CONTRACT-MAP-V0.1.md)。本段只给制定契约的依据，不表示公开接口已实现或所有建议已获采纳。
