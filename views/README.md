# views — WEX 视图体系（架构研究与未来源码职责）

**状态：仅建立归属边界与文档，尚无视图引擎产品代码。** 本目录不代表另起一套画布框架，也不代表已冻结数据协议或节点类型。

## 责任范围

- 视图是 WEX 对象/关系/进度在特定专业语境下的**呈现和交互**，不是业务状态权威，也不是工作流执行引擎。
- 需求树、架构树、验证图、任务进度图等多数视图不执行；**数据关联不等于执行依赖，映射不等于复制状态**。同一进度事件可在不同视图投影为不同含义。
- 软件开发、研究、管理等专业模板可有同名节点，却采用不同语义、配置和运行规则；UI 节点组件不能决定业务执行。
- 二维 React Flow、多视图协作和未来三维关系图都是**候选呈现方式**。视图技术不能定义 WEX 对象身份、关系映射、任务状态或权限。
- 稳定 ID/跨图映射、编辑草稿修订、关联传播暂停/冲突恢复、三维及多项目性能研究**暂缓至 PC 可实测后**，不预建实现子目录或协议。

## 现有可运行研究入口

目前二维画布原型仍原位保留在 [workflows/editor/prototype/](../workflows/editor/prototype/README.md)；该位置是历史实验归属，不意味着所有未来专业视图必须属于执行工作流。待实际验证多类视图后再决定是否移动、复用或重写，**本批不迁移原型文件**。

## 第二批：业务关系与视图映射的维护方

| 数据 | 权威维护方 | views 的作用 |
|---|---|---|
| Context 放置/资源选择 | `space` | 查询与组织展示 |
| 任务依赖/工作流执行路线 | `workflows` | 受控编辑入口与运行投影 |
| 专业对象及关系（如需求对应架构项） | 对应 `workflows/modes` 专业规则；具体模型未定 | 不复制对象状态，不把关系默认为执行路线 |
| 某对象在某视图中的出现/映射、布局/筛选 | `views` 的视图配置责任 | 引用稳定目标，维护呈现，不授予目标访问权 |
| 操作结果、任务进展及核验结论 | `connections` / `workflows` 各自的事实 | 根据来源与版本生成可重建的进度投影 |

同一 Task 可在任务图显示“执行完毕”，在架构图显示“待核验”，在验收图仍未通过；只有映射规则明确关联的视图才更新，不要求所有图同步成同一个颜色/状态。投影保留来源与新旧依据；落后、来源不可用或撤权时应标注/隐藏适当内容，不能把缓存继续冒充当前事实。

草稿暂停关联传播不锁全部图、不停止在途工作；发布草稿须核对所依赖对象与关系的变更，不能用草稿覆盖已经发生的执行结果。跨视图编辑仍调用唯一领域写入口；不能直接修改投影来完成任务。

本表仅为职责分配，不冻结视图配置、关系 schema、传播算法或专业节点格式。当前 `prototype/model.mjs` 虽把定义/坐标放在一个草稿中，仍仅是编辑实验；不迁移代码，也不认作正式多视图层已实现。
