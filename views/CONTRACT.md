# views 业务契约草案

第四批文档设计；基线 `owla19s-ux/WEXPC1@a62996af9863e60b15e4513389c7654719907920`。名称描述能力，不冻结类型/IPC/schema/状态枚举。

## owner 与证据

views 拥有对象在视图中的出现/呈现映射、布局/筛选配置和可重建投影。专业业务关系归对应领域或 modes；执行依赖归 workflows；Task、回执、核验与授权各归原 owner。映射不创建执行依赖，布局不改变业务关系，进度颜色不成为执行状态。

依据：views/README、研究决策 §6–8、全局地图 L08/L12、视图审计、功能全景，以及 workflows/editor 的 README、prototype README/验证报告、App.tsx/model.mjs。现有原型四节点三边、不可变 applyEdit、baseRevision 拒绝、保存成功后提交、选择态独立是历史实验依据。Draft 混合 position/定义、浅导入校验、未接 viewport、单 localStorage、无授权/多图均是限制；toFlow 与 React Flow Node/Edge 不构成正式模型。历史 5 模型+6 DOM/构建/HTTP 通过，不证明真实拖拽/Electron/本契约实现。

## 公开能力

所有查询/编辑由可信宿主确定主体、入口和目标；Context 为可空范围线索，不构成授权。无权目标与不存在目标向无权消费者等价不可用，不返回标签、布局中泄漏的标题、数量或来源定位。下面为 B 推荐行为。

所有映射/布局/发布及转交领域的变更区分**确定未提交、确认提交、提交未知**（证据语义，不冻结枚举）。确定未提交才显示未保存；ACK 或按原业务关联回读可确认提交。保存 ACK 丢失/超时显示待核对，保留关联并回读 owner，不重写、不补偿删改，不以暂未查到证明未提交。原型 localStorage 同步失败的“未推进修订”证据不外推到异步桥/真实存储。

| 能力、目的与消费者 | 前提与权威行为 | 拒绝/失败、并发、恢复及具体断言 |
|---|---|---|
| 打开/查询视图：UI 获取某种专业呈现 | 有权读取视图及其中目标；可无 Context/Task；views 返回获准配置、投影来源与新旧依据，而非嵌入任务真相。可用部分数据须明确范围缺失 | 来源超时/断连保留不可用或过期标识，禁止缓存冒充当前事实。打开取消只结束读取，不停任务。重复读取无写入副作用；旧响应不覆盖更新来源。断言：同一 Task 在任务图已执行、架构图待核验、验收图未通过可并存 |
| 增删出现/呈现映射：UI/mode 配置同对象多处显示 | views 写视图配置修订；验证目标可引用和映射规则，不复制目标。删除一次出现只解除该视图配置；对象可在其他图继续出现 | 源对象不可读不先泄漏“存在”；确定未提交不显示已保存，提交未知显示待核对。重复请求按配置变更关联核对；基线冲突拒绝静默覆盖。断言：新增出现已提交但 ACK 丢失，回读原关联确认只有一次提交、一个出现；不重写或补偿删除；删除出现不删 Task/执行依赖 |
| 修改布局/筛选/视口：交互或布局算法排列同一业务 | 仅更新 views 布局修订；临时选中/悬停无领域写入；自动布局携输入对象/布局基线。React Flow 变化显式转换为布局请求 | 过期异步布局不得覆盖较新手动移动；非法坐标/目标视图拒绝；确定未提交提示未保存，提交未知提示待核对并按原关联回读。重复移动请求不重复推进业务修订。断言：布局R5已提交 ACK 丢失，回读恢复R5且只提交一次；R4旧计算不能覆盖R5或修改Task |
| 发起业务编辑：UI 从图中修改名称/专业关系/执行依赖 | 分辨动作目标 owner；重命名 Task 经 workflows，需求—架构关联经 mode，执行连线经 workflows 校验。用户与 AI 同一领域入口、主体、修订/权限校验；views 只回显已提交结果 | 模式不兼容、授权拒绝、环路/规则失败由 owner 拒绝且视图不先定稿。超时按原变更关联查询，不重复提交潜在副作用。断言：画一条需求—架构映射不启动 Task、不自动产生任务依赖；相同文字“审查”不决定规则 |
| 接收来源变化/重建投影：UI 查看工作和核验进展 | 仅使用获准、可追溯领域事实；比较各来源版本，不要求不同来源共享全局序号。通知提示回读；views 可缓存派生数据，无直接设 Task 正式状态出口 | 重复/乱序通知不倒退已知来源；缺失通知可回读重建。失联显示来源不可用；撤权清理/遮蔽可见缓存与后续订阅，不返回旧敏感内容。断言：收到 Task R9 后再来 R8，显示不回退；撤权后旧详情不可从另一图打开 |
| 暂停传播/编辑草稿/发布恢复：用户独立调整映射 | 暂停仅影响该配置指定的投影传播；明确当前依据滞后。发布核对目标、专业关系与布局基线，写 views 配置；业务变更仍逐 owner 提交 | 不锁全部图、不停止在途任务。发布时 Task 已完成，不准用草稿旧状态覆盖结果；冲突展示可重读/重新编辑，不能承诺跨域全有或全无。恢复先获取当前来源再重算。断言：暂停架构图期间任务图继续更新，恢复后按当前核验事实重建而非重放旧颜色 |

## 最小依赖与内部装配

workflows 提供获准 Task/定义/执行依赖/核验事实的来源版本与受控编辑；modes 提供专业对象/关系及规则身份/兼容判断；space 提供获准组织定位；permissions 提供视图和目标访问/编辑判定；connections 仅在需要显示操作证据时给获准回执摘要；shared 提供配置持久化结果。views 不要求任何领域返回 React Flow 对象，不导入领域私有存储。

app 装配这些窄能力；图形库、自动布局、投影缓存/选择管理属于私有实现，可替换。通知可重复/丢失，断线重连需回读，不用通知直接改领域状态。取消订阅只释放视图资源。施工按需在 views 添加配置/投影实现与 tests；现有 editor/prototype 保留原位，未经实测不迁移/重写；专业面板随 mode，通用导航归 UI。

## 替身与验收

消费者测试：用来源替身产生 Task R9、迟到 R8、核验仍缺失、失联、撤权、同名不同 mode；断言不倒退、不泄漏、不将映射执行。提供方测试使用相同业务样例验证真实 views 的配置修订/回读/暂停行为。依赖提供方须验证确实提供来源版本与获准子集；替身不得用自造同一状态代替工作、核验、验收三种事实。

组合测试必须接真实 workflows/mode/权限与配置存储：一个 Task 在三图投影、两窗口冲突、断线后缺失通知重建、撤权缓存处理、草稿发布与运行并发、异步布局过期、编辑拒绝不落盘。真实鼠标/连线命中、Electron 生命周期、100/500/1000 节点及不同密度/多图性能另作窄实验，不许从四节点推规模承诺。完成证据包含命令/环境/来源修订、持久配置前后、领域无意外写入与资源释放；本批未运行。

### 多来源投影与运行定义对照（F02/F07/F09）

建议在编辑/运行同时显示时区分草稿修订、已发布定义修订、运行绑定修订与各来源当前观察；混合来源版本不宣称一个全局一致快照。已发布r5删节点而实例仍跑r4时，历史节点保留原身份/关联或明确不在当前定义；不能把旧回执涂到r5同名节点。图形撤销只撤销相应编辑意图，不撤销外部执行。

来源输入/产物/规则改变导致核验适用性变化，由workflows返回当前结论，views显示过期或待重核，不独立判验收。搜索命中/通知入口也先查询当前获准投影；缓存缺盘/撤权不返回私有标题/摘要。非开发工作可呈现章节、证据或批次的可选映射，不强制代码架构树或Git关系。

断言：r4与r5同名N不能共用任务颜色；不同来源响应时刻不一时显示来源依据而非“全部同步”；旧搜索结果点击时权限已撤不继续打开缓存。缺专业模式不影响通用列表/工作查询；不据本节批准新视图产品范围。
