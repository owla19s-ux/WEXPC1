# 模型调用协调：一次性行为试点

日期：2026-10-29。状态：实验，不是产品实现或正式 SDK。
对应：[源码边界建议](../../docs/WEXPC-BOUNDARY-DECISION-NOTES-V0.1.md)。

## 问题和范围

验证会话消费方与厂商协议解耦、保存失败不重发、调用结束与取消请求区分，以及在途实现替换的约束。独立编写模拟实现，没有从产品仓提取代码，因此不能证明现有产品已经完成重构或生产调用链兼容。

环境：Linux、Node v24.22.1；没有 Rust/Cargo 或 TypeScript 类型检查器。本实验使用 TypeScript 源码由 Node 类型擦除运行；运行通过不等于 tsc 静态类型检查通过。不新增第三种产品编程语言，也不据此选择 Node 为产品扩展运行时。

运行：`node experiments/model-coordination-spike/verify.ts`。从仓库根目录执行，无依赖安装。

## 文件职责

- api.ts：公开事件与适配器类型、注册与代次、输入绑定、一次生成记录、结束核验。
- conversation.ts：消费公共 API，保存回合投影；保存失败保留内存待保存结果。
- adapters.ts：两种固定的模拟响应格式，只在适配器内部解释。
- verify.ts：确定性行为与故障检查。注册接线在测试入口，产品运行时发现未实现。

这是刻意缩小的维护布局，不是最终目录规范。两个适配器放一起只是缩短试点；真正发布时各模块可以独立携带实现。

## 已运行结果

执行退出码 0，六组检查全部通过：
1. 同一 Conversation 消费者使用两个模拟协议得到一致结果；消费者不导入具体适配器。
2. 注入保存失败后补保存；计数适配器确认模型只调用一次。
3. 适配器抛错或没有明确结束事件时不标成功，并保留部分文本及远端未知。
4. 运行中替换拒绝；取消请求后收到明确成功仍保留成功及取消请求事实；替换后旧回调不改变旧结果，新调用使用新实现。
5. 没有确认结束的取消保留远端未知；相同调用 ID 再次发起被拒绝。
6. 调用方修改原输入对象不改变已准入调用的模型绑定。

占用持续到适配器 Promise 结束，不仅看业务终态；即使已发 done，适配器尚未返回也不应被视为可安全替换。

## 能得出的结论

在此最小模拟条件下，会话可以只依赖公共调用入口，协议格式不需要进入会话代码；结果保存重试与模型执行重试可以分离。建议继续以 API 内公共调用协调为窄试点方向。

这是两个预先存在的适配器使用相同消费者的结构证据，不是“在真实产品新增厂商只改一个文件”的实测。事件和错误模型不具备完整产品表达能力，不冻结当前类型签名。

## 明确未验证及已知限制

- Rust/Tauri、Windows、动态包发现、真实 UI 挂载和外部厂商均未验证。
- 所有记录、注册和保存失败缓存都在内存；进程退出会丢失。没有恢复、数据库事务或跨进程消息。
- cancel 仅登记请求，不中断执行；不能推断远端停止。本地取消状态也不证明网络已经关闭。
- 不含权限、凭证、受控网络、OS 隔离或安全边界；不可用于不可信插件。
- 不处理工具执行、多回合、任务和模板；一个测试回合使用一个模型请求，不代表最终回合/请求关系。
- 没有超时、背压、事件序列、用量、工具提议与不兼容版本协商；挂死适配器会持续占用。
- active 只追踪适配器 Promise，不追踪其私自启动的后台任务；不是资源隔离或完整卸载证明。
- done 被当成可信适配器的确认信号，未对真实厂商结束码或证据做验证。
- TypeScript 类型未静态检查，运行检查覆盖的只是这里列出的行为。
