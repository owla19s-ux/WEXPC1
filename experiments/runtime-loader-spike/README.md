# 运行时加载机制实验（可丢弃）

日期：2026-10-29。状态：Node/Linux 机制实验已执行；不是产品实现，不证明完整方案通过。

运行：`node experiments/runtime-loader-spike/verify.mjs`。无第三方依赖；脚本建立临时包目录，结束后删除。

## 已执行证据

环境 Node v24.22.1，Linux。命令退出码 0。宿主 PID 2，先后 worker PID 16、24（仅本次环境观察，复跑数字会变化）。

8 项检查通过：
1. 宿主启动后新增的包被扫描发现。
2. 新包后端在子进程加载并返回调用结果。
3. 包内静态面板 HTML 由 HTTP 提供。
4. 在途请求存在时停用返回 BUSY。
5. 停用后能力调用拒绝，面板地址返回 404。
6. 更新为第二版后使用新进程，旧激活代次拒绝，宿主 PID 不变。
7. 重复 ID 扫描拒绝，既有实现未被替换。
8. 坏包初始化失败不发布注册，原模块仍能调用。

## 证明范围

只证明独立扩展进程、运行中扫描、受控换版和激活代次检查这条机制可行。测试包返回简单文本，不是模型协议适配器。面板没有运行脚本或消息桥。

NOT_RUN：Rust/Tauri 接线、真实浏览器渲染／UI 挂载／消息桥、Windows、真实模型协议、权限沙箱、持久化恢复、依赖图、数据迁移、资源压力及真实取消。

当前环境未发现 rustc/cargo，因此使用 Node 宿主替身。不能把主进程不变报告为 WEX 已实现热加载。

## 原型限制

仅可信测试包；子进程不是权限隔离。扫描手动触发，不含目录监听与复制完成协议。准备阶段运行扩展顶层代码，不能保证无外部副作用。初始化握手设超时，普通调用与退出的生产超时机制尚未实现。HTTP 仅绑定回环地址，没有生产鉴权；只服务无脚本静态页面，CSP 禁止嵌入，不代表最终面板方案。包版本目录及不可变资源管理未实现，试验只在停用后替换文件。真实权限、认证、消息上限、背压、强制退出恢复均未实现。

不要将此代码直接搬入 WEXPC。后续需先做 Rust/Tauri + 实际 UI 的贯通验证，才判断运行时路线。
