# 接口与通信边界设计

第四批设计稿，2026-10-31；基线 WEXPC1 `a62996af9863e60b15e4513389c7654719907920`。领域语义在各模块 CONTRACT.md；本页只维护跨环境关系。A=既定约束，B=推荐未批准，C=待实验，D=待用户决策。除标A的既定边界外，接口组织方法均为B；不冻结channel、schema、TS签名、数据库或取消保证。

## 1. 通信边界

| 边界 | 身份/准入与能力 | 关联、错误和恢复 | 兼容与验证 |
|---|---|---|---|
| 同进程模块 | 提供方公开操作；消费者窄依赖端口；宿主可信主体/入口，领域复核授权与不变量 | 命令关联、业务结果与持久操作引用分开；异常不自动等于未提交 | 普通调用/显式注入即可；无传输需求不加JSON/IPC；类型和业务样例同时验证 |
| Electron UI→preload→Node | A：隔离renderer、受限桥接、宿主校验来源（依据下述已确认§9）；B：窗口/导航代次绑定可信主体；仅窄业务操作，不暴露SQL/fs/exec万能口 | UI请求号不是业务幂等身份；宿主重启/超时先查询原命令和操作，不以重发补救 | C：WindowsIPC、窗口重建、导航后旧回调、撤权与桥接重连；不先定channel |
| WEX↔独立插件进程 | 宿主绑定实例身份/代次，每次回调检查目标/范围；不信包名和自报Context；只给注入窄服务 | 旧实例结果不能写入新实例；崩溃/卸载不证明未发生副作用；保留观察证据 | C：握手/认证/重放/大小限制/实际OS限权；plugins完整包协议暂缓 |
| WEX↔外部Agent | 出入口授权与外部服务身份分开；按真实支持声明submit/observe/query/resume/interrupt/close | 意图、attempt、外部session/turn/job、cwd与backend分别关联；detach/stop/退出/回滚不可互换 | A：DSH首期；B：固定版本能力协商；不支持明确拒绝，不能用DSH协议统一所有Agent |
| 文件/终端/Git | 宿主准入+实际OS范围；检查路径身份、cwd、重解析点、Git共享元数据 | 关联基线、实际命令/环境/退出/日志/diff；kill不证明后代停止或无部分写入 | C：Windows进程树、锁、路径别名/冲突；适配器验证转义和输出限额 |
| API/GitHub等远端 | 目标endpoint/凭证用途/目标资源均受限；配置编辑不自动授权调用 | 厂商request ID/资源版本与attempt关联；网络失败先查结果，有服务端去重才按其契约使用 | 厂商HTTP/SSE/SDK错误保留原始来源后映射；不承诺跨服务恰好一次 |

A：普通内部操作不全部通过Connections或IPC。对外出口/回调经受控边界；app装配领域公开能力，不交出数据库、容器、Electron event、凭证库或可变宿主整体。双向通信不意味着双向源码依赖。

## 2. 公开接口分面与信息语义

每模块区分消费者公开操作、查询投影、可观察变化、消费者自身窄依赖、私有实现及app装配入口；不是要求新建六个TS文件。提供方拥有业务语义，消费者端口不能削掉提供方前提。

跨边界须表达下列语义（B，非强制统一字段/包）：

- 可信主体及入口由宿主认证环境提供，不能采信模型输出；Context/Conversation/Task可空，空值不表示全局权限。
- 资源的稳定身份/来源、动作、有效范围和预期版本；名称、路径和界面序号不代替权限，查询存在性也受控制。
- UI/传输request、业务意图、单次attempt、外部定位分别关联；一个意图可有多次被允许尝试，不合并账本。关联身份持久期和去重窗口须由提供方声明。
- 对象修订、配置/授权版本、流程定义、进程代次、数据格式和wire版本分别解释；不能用一份revision替代全部版本。
- 来源观察与持久确认分别报告；证据对应来源/版本/环境。公共错误和通知不含密钥/无权目标细节。

响应“接收”不等于执行授权；attempt已存不等于外发；流式内容不等于最终消息已保存；外部completed不等于WEX验收。

## 3. 失败、取消与恢复

| 观察 | 允许推断 | 禁止推断及后续 |
|---|---|---|
| 拒绝 | 当前入口未准入动作 | 不泄露无权目标；不能换入口合权重试 |
| 确认未提交/未派发 | 有证据未跨过该边界副作用点 | 只对本次适用；重试仍查授权/版本/占用 |
| 执行失败 | 某来源阶段失败 | 不能推出没有部分改动，不能直接释放未知占用 |
| 超时/断连 | 等待上限/通信失效 | 结果可能成功、部分执行或仍运行；查询/核验原尝试 |
| 提交未知 | 正式记录可能已提交 | 不报告“没改”；按命令关联读回，证据不足保持未知 |
| 结果已知、回执未确认 | 已有观察，持久状态未确认 | observed与保存状态分开；不重做动作补账 |
| 请求取消 | 已请求有能力的执行方停止 | 支持情况、停止确认及残余影响分开；不支持不能伪造cancelled |
| 取消订阅/关窗口 | 本地停止观察 | 不等于停止任务；保留定位后可查询 |

建议通知消费者按“可丢失、重复、乱序”的保守前提处理；这不是新消息总线承诺。通知只提示可重新授权查询的版本/关联；不直接推进Task。提供方如支持序列补拉须单独声明/测试，否则以获准快照重建。撤权停止订阅、隐藏/清理不再可见缓存的时序为C。

幂等只在提供方规定了意图作用域、请求一致性、保留期、并发重复时才成立；不能拿传输request号推导恰好一次。未知请求先查持久记录与外部资源，缺查询能力升级核对，不虚构恢复API。停止本地等待不构成安全重派依据。

## 4. 兼容与多AI变更

| 类别 | 判定 | 最小验证 |
|---|---|---|
| 内部重构 | 导出/可观察行为/副作用不变 | 本域行为、旧消费样例和依赖边界 |
| 兼容扩展候选 | 旧消费者真实预期不变 | 旧输入、严格解析/穷尽分支、动态注册；新增可选字段或错误不自动兼容 |
| 破坏变更 | 同签名下默认权限变宽、timeout从unknown改failed、重发产生新副作用、cancel变detach、配置生效版本改变 | 提供/消费双方审查，迁移/限期适配或明确拒绝；TS编译绿不足 |
| wire/data兼容 | 编码、握手、数据迁移、外部协议分别评估 | 固定版本组合、旧结果重放、升级降级及不支持行为 |

B：同仓以提交/构建组合锁定、就近记录语义修订，不预发每目录SDK。跨进程核验对端实现/协议和实际能力；不兼容拒绝或只开放被证明兼容查询，不能在“只读模式”悄悄迁移。回退不允许静默剥除授权条件。

提供方维护承诺，消费者维护使用样例；公开变更列受影响模块、注册/配置使用者、A/B/C/D及迁移限制。app/桥接/公共依赖文件串行整合；模块开发者不顺手改邻域私有实现。每次提交先核对HEAD，不强推覆盖；替身全绿仅算本域证据，兼容声明需真实提供者和消费者验证。

## 5. 待实验与验收入口

- C-IPC：伪造sender/参数、导航后旧回调、无权目标、重复迟到回复、超大输入、宿主重启与桥接断开；拒绝不得先取数，不隐式重派。具体限额待能力/实测确定。
- C-PLUGIN：伪造身份、旧实例回调、重放、撤权后读、挂死/崩溃/残留进程、磁盘网络直达；独立进程不是权限沙箱。
- C-AGENT：每固定版本分别验证submit、session/turn、流、resume/query/interrupt、cwd/backend和真实产物；headless/SDK/ACP不能合成全能接口。
- C-RECOVERY：派发/保存前后崩溃、重复乱序结果、旧备份恢复但外部已改、资源未释放；保持unknown而不是自动重派。
