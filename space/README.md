# space — 组织、Context 与引用

状态：第二批架构细化结论（2026-10-30）；尚无产品实现。此处明确职责，不冻结表结构、身份编码或文件格式。

## 唯一维护的内容

| 内容 | 维护责任 | 不随之发生的行为 |
|---|---|---|
| Space 类别、Space 工作区、可选 Group | 组织与入口；工作区可登记用户选择的目录 | 类别/Group 不强制对应目录，也不发放授权 |
| Context 本体与自身配置 | 独立工作环境及其存储定位；不必先有 Space | 不强制创建项目、模板、任务或 Agent |
| Space/Group 对 Context 的放置关系 | 可多处引用同一 Context；显示位置不决定 Context 身份 | 移动/解除一处关联不搬文件、不删本体、不终止任务 |
| Context 选择的资源、连接、角色和其他 Context 引用 | 保存本地组合意图与目标引用 | 不复制目标记录、不替目标领域修改状态、不递归获得对方全部内容 |

同一个 Context 在多个 Space 中显示，仍只有一份本体与一处权威存储定位；其他 Space 保存引用而非另一份 Context 状态。独立 Context 可关联到任意获准的 Space。登记索引用于定位，不是第二份本体；目录失联时保留引用并报告不可用，不静默新建同名 Context。

Context 可以保存自己的资料和组合配置；引用的对话、任务、角色、连接和外部文件分别由所属领域或外部来源维护。资源可能位于不同磁盘、仓库或服务，关联不要求搬迁。Space 工作区目录、独立 Context 目录与公共数据根互不等同，详见[目录要求](../docs/WEXPC-SOURCE-LAYOUT-AND-WINDOWS-DATA-2026-10-30.md)及[两种入口](../docs/WEXPC-SPACE-AND-WORKFLOW-EDITOR-DESIGN-2026-10-30.md)。

## 关系修改与权限

- `space` 只维护组织/选择关系；实际职责绑定归 [AI/roles](../AI/roles/README.md)，会话采用的背景归 [conversations](../conversations/README.md)，任务依赖归 [workflows](../workflows/README.md)。反向列表由查询派生，不能双方各写一份。
- A/B 两个 Space 引用同一 Context，不把 A 的入口授权带到 B，也不求并集；实际读取/修改须按当前主体、入口、目标与动作交 [permissions](../permissions/README.md) 判断。无权目标不能通过名称、统计或反向引用泄露。
- 引用变更只作用于该关系；删除本体是不同操作，须检查其他引用、在途工作和删除授权，不能由“移出 Group”隐含执行。失效/无权引用的呈现由查询边界处理，不由 UI 猜测目标已删除。
- 软件开发等模式只是可选组合预设，移除模式不自动删除已建立的通用对象，模板也不能改变通用 Context 的性质。

待验证：多目录重启定位、复制目录带来的身份冲突、重定位/删除并发、跨存储关系提交的一致性。当前只确定不复制权威、不隐式删除与不借引用扩权；具体合并、恢复和事务方式未定。

跨领域责任与场景 S1 见[统一审查](../docs/WEXPC1-RESEARCH-DECISIONS-2026-10-30.md#7-七个场景的架构对冲检查)。
